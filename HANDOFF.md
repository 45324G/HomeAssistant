# 1. Ключевое: где живёт Claude Code

Это главное недоразумение, которое надо снять сразу.

**Home Assistant OS — не обычный Linux.** Это закрытая система-прибор. Нет `apt`,
нет установки программ, нет полноценной командной строки. **Claude Code туда поставить
нельзя, и не нужно.**

```
┌─────────────────────────┐         ┌──────────────────────────┐
│  РАБОЧИЙ НОУТБУК        │         │  NUC                     │
│  (Windows)              │         │  Home Assistant OS       │
│                         │         │                          │
│  Claude Code  ──────────┼─SSH────►│  дополнение SSH          │
│                         │         │  команда ha              │
│               ──────────┼─ha-mcp─►│  автоматизации, конфиги  │
│  Браузер      ──────────┼─:8123──►│  веб-интерфейс           │
└─────────────────────────┘         └──────────────────────────┘
```

Claude Code на ноутбуке, дом на NUC, связь по сети. Команды пишете у себя — выполняются там.

**Что понадобится на ноутбуке:** только `ssh`, он уже встроен в Windows. Ставить ничего
не нужно.

**Единственное, что нельзя удалённо** — первая установка системы: записать флешку,
зайти в BIOS, загрузиться. Полчаса с телевизором. После этого всё делается с ноутбука.

# 3. Архитектура и почему так

## Платформа: HAOS на голое железо

Home Assistant OS ставится **прямо на внутренний NVMe**. Windows стирается.
Гипервизора нет.

**Рассмотренные и отвергнутые варианты:**

| Вариант | Почему нет |
|---|---|
| Windows + Hyper-V | Лишний слой, ночные перезагрузки от обновлений, нужен сторож для перезапуска зависшей системы |
| Proxmox + виртуалка | Берёт статический IP при установке — ломает переезд между сетями. Bluetooth недоступен. Проброс видеоядра сложнее прямого доступа. Вторая система на обслуживании |
| Debian + Docker | Нет магазина дополнений: Zigbee2MQTT, Mosquitto и прочее придётся вести вручную. Ровно та работа, которой владелец не хочет |
| HA Supervised | Поддержка прекращена в декабре 2025 |

## Три уровня надёжности

Главный принцип. Важнее любого технического выбора.

```
УРОВЕНЬ 0 — работает всегда
  Физические выключатели на стенах, кнопки на розетках
  Не зависит ни от чего

УРОВЕНЬ 1 — ежедневный свет
  Лампы Matter. Управление локальное, интернет не нужен

УРОВЕНЬ 2 — умный дом
  Home Assistant: автоматизации, датчики, сценарии, AI
  Здесь вся сложность и все зависимости
```

**Правило:** ни одно устройство не должно управляться только через Home Assistant.
Если что-то нельзя включить рукой — это точка отказа, которая однажды оставит семью
без света.

## Роли AI

| Роль | Чем | Где работает |
|---|---|---|
| Создание и отладка автоматизаций | Claude Code + ha-mcp | На ноутбуке владельца |
| Круглосуточный обработчик команд | YandexGPT — **опционально, не на старте** | Внутри Home Assistant |

YandexGPT платится российской картой. Но его качество в разборе русских намерений
не проверено, поэтому в ежедневный путь он не ставится, пока владелец сам не убедится.

## Удалённый доступ

CGNAT исключает входящие соединения. Схема — туннель изнутри наружу:

```
Дом (CGNAT)            VPS в Казахстане          Владелец вне дома
┌──────────┐           ┌──────────────┐          ┌──────────┐
│ NUC      │──наружу──►│ публичный    │◄─────────│ ноутбук  │
│ + туннель│           │ адрес        │          │ телефон  │
└──────────┘           └──────────────┘          └──────────┘
```

**Протокол — AmneziaWG, не обычный WireGuard:** последний в России распознаётся
и глушится системами анализа трафика.

**Второе применение того же сервера:** обратный прокси с HTTPS для прямого подключения
Алисы. Это позволяет отказаться от стороннего ретранслятора `yaha-cloud.ru`, через
который иначе шли бы голосовые команды — сервер частного лица в ежедневном пути.

# 4. Открытая развилка — решает владелец

## Куда вести лампы YNDX-00551

Лампы работают по **Matter over Wi-Fi**. Управление **локальное в обоих вариантах** —
разница только в том, кто контроллер. Одновременно в двух экосистемах Яндекс их держать
не даёт.

| Ситуация | Лампы у Яндекса | Лампы в Home Assistant |
|---|---|---|
| Управление | Локальное | Локальное |
| Интернет пропал | ✅ Алиса управляет голосом | ❌ Алиса их не видит |
| Home Assistant сломался | ✅ Работают | ❌ Не работают |
| Сторонний ретранслятор в пути | Да, когда командует HA | Нет никогда |
| Выключатель на стене | ✅ Всегда | ✅ Всегда |

**Рекомендация: вести в Home Assistant.** Из ежедневного пути убирается посредник.
Теряется только голос в момент обрыва интернета — но тогда и свои фразы Алисы всё
равно не работают, а выключатель работает.

# 5. Установка — по этапам

## Этап 0. Купить

| Что | Зачем | Ориентир |
|---|---|---|
| SATA SSD 250–500 ГБ | Резервные копии, во второй отсек NUC | ~2500 ₽ |
| ИБП с USB-подключением | Грязное выключение портит базу данных | ~5000 ₽ |
| Умная розетка с физической кнопкой | Жёсткая перезагрузка NUC с телефона | ~1000 ₽ |
| Флешка от 8 ГБ | Установка | ~500 ₽ |

**ИБП обязательно с USB.** Без передачи данных он только откладывает аварийное
выключение, а не предотвращает его.

## Этап 1. Записать флешку — с ноутбука

Скачать образ: `github.com/home-assistant/operating-system/releases`
Нужен файл вида **`haos_generic-x86-64-XX.X.img.xz`**.

Записать через **Balena Etcher** (`etcher.balena.io`) или Rufus.

> Если GitHub из России открывается плохо — использовать VPN, который у владельца
> уже настроен на рабочем ноутбуке.

## Этап 2. Установка — физически, ~40 минут

**Нужен телевизор с HDMI** (у NUC есть выход HDMI), клавиатура и флешка.

```
1. Вставить SATA SSD во второй отсек NUC (если купили)
2. Подключить NUC кабелем к роутеру Eltex
3. Подключить телевизор и клавиатуру
4. Включить, сразу нажимать F2 — вход в BIOS
5. В BIOS:
     - Secure Boot        → Disabled
     - Boot Mode          → UEFI
     - After Power Failure → Power On     ← важно, нажать кнопку удалённо некому
     - Boot order         → USB первым
6. F10, сохранить, выйти
7. Загрузиться с флешки, установить HAOS на внутренний NVMe
8. Перезагрузиться, вынуть флешку
```

**Внимание:** установщик перезапишет диск целиком. Windows будет стёрта.
Удалённый доступ к NUC исчезнет навсегда в момент загрузки с флешки.

## Этап 3. Первый вход — уже с ноутбука

В браузере: **`http://homeassistant.local:8123`**

Не открылось — найти адрес в роутере (`192.168.1.1`, раздел с клиентами DHCP)
по MAC `1C-69-7A-02-8A-19`.

```
1. Создать аккаунт администратора. Пароль записать
2. Часовой пояс: Europe/Moscow
3. Закрепить адрес на роутере:
     192.168.1.1 → LAN → DHCP → Резервирование
     MAC 1C-69-7A-02-8A-19  →  192.168.1.10
```

## Этап 4. Дополнение SSH — открывает дорогу всему остальному

В веб-интерфейсе: **Настройки → Дополнения → Магазин дополнений**

Найти **«Advanced SSH & Web Terminal»**, установить.

В настройках дополнения:
```yaml
username: hassio
password: "ПРИДУМАТЬ_ПАРОЛЬ"
```

Отключить **Protection mode** (иначе не будет полного доступа к системе).
Включить **Start on boot** и **Watchdog**. Запустить.

**Проверка с ноутбука** — в PowerShell:
```powershell
ssh hassio@192.168.1.10
```

Заработало — дальше всё делается отсюда, телевизор больше не нужен.

## Этап 5. Всё остальное — командами с ноутбука

С этого момента ассистент работает по SSH. Порядок:

```
1. Включить ежедневные резервные копии — ДО всего остального
2. Настроить recorder с исключениями (раздел 6)
3. git init в /config
4. Донгл: кабель в роутер, закрепить 192.168.1.11, проверить прошивку
5. Mosquitto → Zigbee2MQTT
6. Привязать устройства: сначала розетки и реле, потом датчики
7. HACS
8. LocalTuya (форк xZetsubou)
9. yandex_smart_home, YandexStation
10. ha-mcp — в режиме только чтения
11. AmneziaWG до KZ-сервера
12. Проверить восстановление из копии
```

# 6. Конфигурации

## recorder — настроить сразу, до накопления данных

В `/config/configuration.yaml`:

```yaml
recorder:
  purge_keep_days: 10
  commit_interval: 30
  exclude:
    domains:
      - updater
      - automation
    entity_globs:
      - sensor.*_linkquality
      - sensor.*_rssi
      - sensor.*_last_seen
      - sensor.*_update_available
    entities:
      - sun.sun
```

**Зачем:** по умолчанию Home Assistant пишет каждое изменение каждого датчика.
Розетки с замером мощности шлют данные каждые несколько секунд. Без этих исключений
база вырастает до нескольких гигабайт за пару месяцев, интерфейс начинает тормозить,
а SSD без буфера изнашивается.

## Zigbee2MQTT

В `/addon_configs/.../zigbee2mqtt/configuration.yaml`:

```yaml
mqtt:
  server: mqtt://core-mosquitto
  user: mqtt_user
  password: "ПАРОЛЬ_ИЗ_НАСТРОЕК_MOSQUITTO"

serial:
  port: tcp://192.168.1.11:6638
  adapter: ember
  baudrate: 115200

homeassistant:
  enabled: true

frontend:
  enabled: true
  port: 8099

advanced:
  log_level: info
  network_key: GENERATE
  pan_id: GENERATE
  channel: 25
```

**`adapter: ember` — критично.** Донгл построен на Silicon Labs EFR32MG24. Устаревшее
имя `ezsp` и тип `zstack` (от старого Dongle Plus) приведут к тому, что Zigbee2MQTT
не запустится. Это самая частая ошибка с этим устройством.

**Канал 25** — минимальное пересечение с Wi-Fi 2.4 ГГц, на котором висит 13 устройств.

**Перед привязкой устройств проверить прошивку донгла** в его веб-консоли:
для драйвера `ember` нужен EmberZNet не ниже 7.4.

## Порядок привязки Zigbee

**Сначала все устройства с постоянным питанием, потом батарейные.**

Розетки и реле работают ретрансляторами и строят сеть. Датчики и кнопки только
принимают. Если подключить датчики первыми, они свяжутся напрямую с координатором
через всю квартиру и будут отваливаться.

```
Сначала:  реле HOMMYN, розетки Tuya, реле без нейтрали, диммер, проводные выключатели
Потом:    датчики температуры, датчики протечки, беспроводные выключатели, кнопки
```

Подключать **по одному**, сразу проверяя, что устройство появилось в Home Assistant
с рабочими кнопками. Вести табличку: устройство, модель в Z2M, работает или нет.

# 7. Безопасность AI-слоя

Формулировки ниже уточнены после разбора — прошлые были завышены.

**Чего НЕ делают заявленные меры:**

- «Отдельный пользователь без прав администратора» **не защищает**: правка автоматизаций
  идёт через конфигурационный API, который требует администратора. Включили запись —
  токен административный.
- «Список открытых сущностей» ограничивает **только** Assist API (YandexGPT, встроенный
  MCP). Для ha-mcp неверно: он работает через REST и WebSocket и видит всё.

**Что работает:**

```
1. Ничего опасного для жизни и имущества не отдавать модели вообще.
   В списке устройств нет замков, ворот и отопления — так и оставить.
   Максимальный ущерб при худшем раскладе: помигал свет.

2. Метка на всех автоматизациях, созданных моделью,
   и один переключатель, отключающий их разом.

3. mode: single на каждой автоматизации от модели.
   Реле без нейтрали и диммер — самое хрупкое железо в доме,
   зацикливание с 50 переключениями в минуту их убьёт.

4. Запретить на уровне политики ha-mcp:
   перезапуск Home Assistant, перезагрузку интеграций,
   любые инструменты работы с Zigbee2MQTT и MQTT.

5. Режим только чтения, пока восстановление из копии
   не проверено хотя бы один раз на практике.

6. git init в /config, коммит раз в сутки.
   Ошибка модели становится git diff, а не раскопками.

7. ha-mcp — только внутри локальной сети и туннеля.
   Его адрес с секретной строкой равносилен административному токену.
```

**Самая вероятная беда — не атака, а несчастный случай:** модель пишет автоматизацию
с триггером без целевого состояния, или две автоматизации начинают вызывать друг друга.
Пункты 2 и 3 важнее всей защиты от злоумышленников.

# 8. Что ещё не проверено

| # | Что | Как проверить | Последствие |
|---|---|---|---|
| 1 | **Изоляция клиентов Wi-Fi на роутере** | Настройки Wi-Fi в `192.168.1.1` | Если включена — Wi-Fi устройства не увидят Home Assistant, Matter-лампы не заработают |

Первый пункт стоит закрыть до установки — он влияет на работу ламп.

# 9. Известные слабые места

Говорить о них честно, не замалчивать.

**Почти весь дополнительный слой — проекты сообщества:** ha-mcp, YandexGPT, LocalTuya,
YandexStation, yandex_smart_home. Часть работает через недокументированные API Яндекса.
Официальны и надёжны только ядро Home Assistant, Zigbee2MQTT, Mosquitto.

**LocalTuya — слабейшее звено.** Оригинальный проект заброшен, живёт форк. Ключи
добываются через кабинет разработчика Tuya — процедура болезненная. **Вывод на будущее:
новые устройства покупать в версии Zigbee, а не Wi-Fi.**

**Сетевой Zigbee-координатор — компромисс.** Добавляет отказы, которых нет у USB-донгла:
сбой сетевой части, смена адреса, перезагрузка роутера. Обязателен кабель и закреплённый
адрес. Связка `ember` + прошивка — главный источник поломок Zigbee2MQTT последних лет,
поэтому резервная копия перед каждым обновлением Z2M.

**У Home Assistant не будет обхода блокировок.** Сейчас на NUC работает VPN-клиент под
Windows — после установки его не станет. HAOS пойдёт в интернет напрямую через Акадо:
Яндекс работает, обновления HA обычно доступны, **GitHub для HACS бывает нестабилен**.

# 10. Правила для ассистента

```
НЕ ДЕЛАТЬ:
  × Не выставлять Home Assistant в интернет напрямую
  × Не давать модели править конфиг Zigbee2MQTT
  × Не включать право записи в ha-mcp до проверки восстановления из копии
  × Не отдавать модели ничего опасного для жизни и имущества
  × Не менять сетевые настройки без предупреждения — можно потерять доступ

ДЕЛАТЬ:
  ✓ Объяснять простыми словами перед каждым шагом
  ✓ Показывать ключевые строки вывода, а не весь лог
  ✓ При ошибке — точный текст, разбор, и только потом дальше
  ✓ Резервная копия перед каждым существенным изменением
  ✓ Дописывать в журнал изменений: что сделано и почему
  ✓ Писать по-русски
```

# 12. Команды — что реально делается командами, а что нет

Честно о границах: **сама установка системы командами не делается.** Записать флешку,
зайти в BIOS, загрузиться — это руками. Командная строка появляется только после того,
как Home Assistant поднялся и в нём включено дополнение SSH.

| Этап | Чем делается |
|---|---|
| Скачать образ, записать флешку | Программа Balena Etcher на ноутбуке, мышкой |
| BIOS, установка на диск | Руками, с телевизором |
| Создать аккаунт, поставить дополнение SSH | Браузер, ~10 минут кликов |
| **Всё остальное** | **Команды с ноутбука** |

Дальше — блоки, которые можно копировать целиком.

## Блок 1. Подключиться с ноутбука

В PowerShell на рабочем ноутбуке. Ставить ничего не нужно, `ssh` уже встроен в Windows.

```powershell
ssh hassio@192.168.1.10
```

Спросит пароль — тот, что задали в настройках дополнения SSH.

Дальше все команды выполняются уже внутри этого соединения.

## Блок 2. Осмотреться

```bash
ha core info
ha os info
ha network info
```

Покажет версии, адрес, состояние. Полезно записать в журнал изменений.

## Блок 3. Резервная копия — до всего остального

```bash
ha backups new --name "chistaya-sistema"
ha backups list
```

**Делать это первым.** Дальше будет к чему вернуться, если что-то пойдёт не так.

## Блок 4. Настройка recorder

Создать конфигурацию до того, как база начнёт расти:

```bash
cd /config
cp configuration.yaml configuration.yaml.backup
nano configuration.yaml
```

Вписать блок `recorder` из раздела 6. Сохранить: `Ctrl+O`, `Enter`, `Ctrl+X`.

Проверить, что не сломали синтаксис, и применить:

```bash
ha core check
ha core restart
```

**`ha core check` обязательно перед перезапуском.** Если в файле ошибка, эта команда
её покажет, а перезапуск с битым конфигом оставит систему лежать.

## Блок 5. Git — чтобы любую ошибку можно было откатить

```bash
cd /config
git init
git add .
git commit -m "Исходное состояние"
```

Дальше после каждого существенного изменения:

```bash
cd /config && git add . && git commit -m "что сделано"
```

Тогда ошибка модели — это `git diff`, а не раскопки.

## Блок 6. Дополнения

Посмотреть, что установлено и какие есть:

```bash
ha addons list
```

Установить и запустить Mosquitto:

```bash
ha addons install core_mosquitto
ha addons start core_mosquitto
ha addons info core_mosquitto
```

> **Ассистенту:** точные имена дополнений (slug) и синтаксис добавления репозиториев
> различаются между версиями. Перед выполнением свериться: `ha addons --help`,
> `ha --help`. Не угадывать — если команда не принята, посмотреть подсказку и
> использовать веб-интерфейс как запасной путь.

Zigbee2MQTT удобнее ставить через магазин дополнений в браузере — он не входит
в стандартный набор, нужно добавлять репозиторий.

## Блок 7. HACS

```bash
wget -O - https://get.hacs.xyz | bash -
ha core restart
```

После перезапуска: в браузере **Настройки → Устройства и службы → Добавить → HACS**.
Понадобится аккаунт GitHub.

> Если команда не проходит — GitHub из России бывает недоступен. Это ожидаемо,
> см. раздел 9.

## Блок 8. Полезное в работе

```bash
# Логи в реальном времени
ha core logs -f

# Логи конкретного дополнения
ha addons logs core_mosquitto

# Перезапуск
ha core restart
ha addons restart core_mosquitto

# Свободное место
df -h

# Размер базы данных
ls -lh /config/home-assistant_v2.db

# Копия перед рискованным изменением
ha backups new --name "pered-$(date +%Y%m%d-%H%M)"
```

## Как это выглядит в работе

После настройки повседневная работа такая:

```
Вы (в Claude Code на ноутбуке):
   «сделай, чтобы свет в коридоре включался по движению после заката
    и гас через 3 минуты»

Claude Code:
   → через ha-mcp создаёт автоматизацию
   → запускает, показывает трассировку
   → сообщает результат
```

Никакого YAML руками, никаких кликов по меню. Но это работает **только после**
того, как система установлена и ha-mcp подключён.
