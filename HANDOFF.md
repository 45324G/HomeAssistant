# 1. Где работает ассистент

**Home Assistant OS — не обычный Linux.** Это закрытая система-прибор: нет `apt`,
нет установки произвольных программ. **AI-ассистент туда поставить нельзя, и не нужно.**

```
┌──────────────────────────┐        ┌──────────────────────────┐
│  РАБОЧИЙ НОУТБУК         │        │  NUC                     │
│  Windows                 │        │  Home Assistant OS       │
│                          │        │                          │
│  AI-ассистент  ──────────┼─SSH───►│  дополнение SSH, `ha`    │
│                ──────────┼─MCP───►│  автоматизации, конфиги  │
│  Браузер       ──────────┼─:8123─►│  веб-интерфейс           │
└──────────────────────────┘        └──────────────────────────┘
```

Ассистент на ноутбуке, дом на NUC, связь по сети. На ноутбуке нужен только `ssh` —
он встроен в Windows.

**Смена AI-вендора ничего не ломает.** Доступ идёт по протоколу MCP, он не привязан
к вендору: подключается любой клиент из командной строки. Переход занимает 10–30 минут,
на стороне Home Assistant не меняется ничего.

**Важно:** веб-версии ассистентов (браузерные) подключаются из облака вендора и через
домашний VPN не пройдут. Нужен клиент **в командной строке или редакторе**, работающий
на машине владельца.

# 3. Три радиомира — не путать

Частая путаница, приводящая к неверным решениям.

```
Zigbee-радио                Wi-Fi                     Bluetooth
через донгл             через роутер              напрямую в NUC
─────────────           ─────────────             ─────────────
Реле HOMMYN             Лампы YNDX (Matter)       CO2 Qingping
Реле Tuya               Розетки Wi-Fi Tuya
Розетки Zigbee          Модули HOMMYN
Датчики                 Камера
Кнопки                  Колонки Яндекс
Диммер                  ← Home Assistant
```

**Донгл обслуживает только Zigbee.** Wi-Fi устройства подключаются к роутеру,
Home Assistant разговаривает с ними по локальной сети напрямую.

**Про Wi-Fi у донгла.** У него есть точка доступа — до 8 маломощных устройств,
официально. **Пользоваться ей не надо:** тот же чип обслуживает Zigbee-сеть из 20
устройств, клиенты отъедают у него ресурсы. Плюс её топология похожа на отдельную
подсеть, а Matter требует, чтобы устройства и Home Assistant были в одной сети.

**Про Thread.** Донгл может быть хабом для Matter-устройств **на Thread**.
Но лампы YNDX работают по Matter **на Wi-Fi** — другой транспорт, донгл не при делах.
Matter — это язык, Thread и Wi-Fi — разные дороги.

**Одновременно Zigbee и Thread донгл вести не может.** Режим MultiPAN в 2026 закрыт:
Home Assistant его удалил, Zigbee2MQTT не поддерживает, разработчики ZHA отказались.

# 4. Архитектура и обоснование

## Платформа: HAOS на голое железо

Home Assistant OS ставится **прямо на внутренний NVMe**. Windows стирается.
Гипервизора нет.

| Отвергнутый вариант | Почему |
|---|---|
| Windows + Hyper-V | Лишний слой, ночные перезагрузки от обновлений, нужен сторож для зависшей системы |
| Proxmox + виртуалка | Статический IP при установке ломает переезд между сетями. Bluetooth недоступен. Проброс видеоядра сложнее прямого доступа. Вторая система на обслуживании |
| Debian + Docker | Нет магазина дополнений — всё вручную. Ровно та работа, которой владелец не хочет |
| HA Supervised | Поддержка прекращена в декабре 2025 |

**Перезапуск зависшей системы** — умная розетка с физической кнопкой (~1000 ₽),
не гипервизор.

## Три уровня надёжности — главный принцип

```
УРОВЕНЬ 0 — работает всегда
  Физические выключатели на стенах, кнопки на розетках
  Не зависит ни от чего

УРОВЕНЬ 1 — ежедневный свет
  Лампы Matter в Home Assistant. Управление локальное, интернет не нужен

УРОВЕНЬ 2 — умный дом
  Автоматизации, датчики, сценарии, AI. Здесь вся сложность
```

**Правило:** ни одно устройство не должно управляться только через Home Assistant.
Что нельзя включить рукой — точка отказа, которая однажды оставит семью без света.

## Роли AI

| Роль | Чем | Где |
|---|---|---|
| Создание и отладка автоматизаций | ha-mcp + ассистент владельца | На ноутбуке |
| Круглосуточный обработчик команд | YandexGPT — **опционально, не на старте** | В Home Assistant |

YandexGPT платится российской картой, но качество разбора русских намерений
не проверено. В ежедневный путь не ставится, пока владелец сам не убедится
сравнением.

## Голос

**Уровень надёжности для супруги — сценарии Яндекса с фразами запуска.**
Фраза → сценарий Яндекса → скрипт Home Assistant → что угодно.

Ограничения: 1–3 фразы на сценарий, ~200 сценариев, **переменные не передаются**.
Числа Алиса понимает своей грамматикой — параметрические команды идут через прямую
отдачу устройств, а не через фразы.

**Принцип: умным делаем сценарий, а не речевой интерфейс.** Супруга произносит
короткую надёжную фразу, вся условная логика живёт в автоматизации.

`ha-yandex-station-intents` (свои фразы в масштабе) — **не на старте**, работает
через недокументированный API Яндекса. Начинаем со штатных сценариев в приложении.

**Микрофон Яндекс Станции недоступен** — превратить колонку в микрофон
для Home Assistant невозможно.

## Удалённый доступ

CGNAT исключает входящие соединения. Схема — туннель изнутри наружу:

```
Дом (CGNAT)            VPS в Казахстане          Владелец вне дома
┌──────────┐           ┌──────────────┐          ┌──────────┐
│ NUC      │──наружу──►│ публичный    │◄─────────│ ноутбук  │
│ + туннель│           │ адрес        │          │ телефон  │
└──────────┘           └──────────────┘          └──────────┘
```

**Протокол — AmneziaWG, не обычный WireGuard:** последний в России распознаётся
системами анализа трафика и глушится. Роутер Eltex AmneziaWG не умеет — туннель
поднимается на стороне NUC.

**Второе применение того же сервера:** обратный прокси с HTTPS для прямого
подключения Алисы. Позволяет отказаться от стороннего ретранслятора
`stream.yaha-cloud.ru` — сервера частного лица, через который иначе шли бы
все голосовые команды.

# 5. Решённое и открытое

## Решено: лампы YNDX ведём в Home Assistant

Управление локальное в обоих вариантах — разница в том, кто контроллер.
Решение убирает посредника из ежедневного пути.

Голос сохраняется: `Алиса → yandex_smart_home → Home Assistant → Matter → лампа`.
Теряется только голос в момент обрыва интернета — но тогда и свои фразы Алисы
не работают, а выключатель работает всегда.

**Следствия:**
- Нужно дополнение **Matter Server** и интеграция Matter
- Лампы, привязанные к Яндексу, **сбросить к заводским** перед привязкой
- Нужен **код Matter** — на корпусе лампы и на коробке
- **Изоляция клиентов Wi-Fi на роутере должна быть выключена**

## ОТКРЫТО: донгл по Ethernet или по USB

**Требует решения владельца до закупки и установки.**

Разработчики Zigbee2MQTT в январе 2026 перевели Dongle-M в раздел
**«не рекомендуется»** до исправления прошивки. Причина — нестабильность
именно **по Ethernet**: обрывы соединения. По USB работает стабильнее.

| | Ethernet | USB |
|---|---|---|
| Стабильность | ⚠️ Есть жалобы на обрывы | ✅ Лучше |
| Размещение донгла | Где угодно в квартире | Только рядом с NUC |
| Покрытие Zigbee | ✅ Можно поставить в центре | ⚠️ Зависит от места NUC |
| Проброс в виртуалку | — | Не нужен, система на голом железе |

**Суть выбора:** устойчивость связи против покрытия Zigbee по квартире.

Если NUC стоит в углу у роутера, а квартира большая — Ethernet даёт лучшее
покрытие, но с риском обрывов. Если NUC примерно в центре — USB надёжнее.

**Рекомендация:** начать с USB как более стабильного, проверить покрытие
по карте сети в Zigbee2MQTT. Не хватает — перейти на Ethernet, это одна строка
в конфигурации. Кабель в любом случае держать под рукой.

## Не проверено

| # | Что | Как | Последствие |
|---|---|---|---|
| 1 | **Изоляция клиентов Wi-Fi** 🔴 | Настройки Wi-Fi в `192.168.1.1` | Блокирует Matter-лампы. У многих роутеров режет и проводных клиентов; даже где не режет — глушит широковещательные запросы, через которые Matter находит устройства |
| 2 | Прошивка донгла | Веб-консоль донгла | Для `ember` нужен EmberZNet ≥ 7.4 |
| 3 | RTSP у камеры Cootli | Приложение камеры | Заведётся ли вообще |
| 4 | Версия протокола Tuya у HOMMYN | При настройке LocalTuya | 3.3 или 3.4 |

Первый пункт закрыть **до установки**.

# 6. Установка по этапам

## Этап 0. Купить

| Что | Зачем | Ориентир |
|---|---|---|
| SATA SSD 250–500 ГБ | Копии, во второй отсек NUC | ~2500 ₽ |
| ИБП **с USB-подключением** | Грязное выключение портит базу | ~5000 ₽ |
| Умная розетка с физической кнопкой | Жёсткая перезагрузка NUC с телефона | ~1000 ₽ |
| Флешка от 8 ГБ | Установка | ~500 ₽ |

ИБП без передачи данных только откладывает аварийное выключение, а не предотвращает.

## Этап 1. Записать флешку — с ноутбука

Образ: `github.com/home-assistant/operating-system/releases`,
файл вида **`haos_generic-x86-64-XX.X.img.xz`**.

Записать через **Balena Etcher** или Rufus.

> GitHub из России бывает недоступен. У владельца на рабочем ноутбуке настроен
> VPN-клиент Happ — использовать его.

## Этап 2. Установка — физически, ~40 минут

Нужен **телевизор с HDMI** (у NUC есть HDMI), клавиатура, флешка.

```
1. Вставить SATA SSD во второй отсек (если куплен)
2. Подключить NUC кабелем к роутеру
3. Подключить телевизор и клавиатуру
4. Включить, сразу нажимать F2 — BIOS
5. В BIOS:
     Secure Boot          → Disabled
     Boot Mode            → UEFI
     After Power Failure  → Power On    ← нажать кнопку удалённо некому
     Boot order           → USB первым
6. F10, сохранить, выйти
7. Загрузиться с флешки, установить на внутренний NVMe
8. Перезагрузиться, вынуть флешку
```

**Установщик перезапишет диск целиком.** Удалённый доступ к NUC исчезнет навсегда
в момент загрузки с флешки.

## Этап 3. Первый вход — с ноутбука

Браузер: **`http://homeassistant.local:8123`**

Не открылось — найти адрес в роутере по MAC `1C-69-7A-02-8A-19`.

```
1. Создать администратора, пароль записать
2. Часовой пояс Europe/Moscow
3. Закрепить адрес на роутере:
     192.168.1.1 → LAN → DHCP → Резервирование
     MAC 1C-69-7A-02-8A-19 → 192.168.1.10
```

## Этап 4. Дополнение SSH

**Настройки → Дополнения → Магазин** → «Advanced SSH & Web Terminal».

```yaml
username: hassio
password: "ПРИДУМАТЬ_ПАРОЛЬ"
```

Отключить **Protection mode**, включить **Start on boot** и **Watchdog**, запустить.

Проверка с ноутбука:
```powershell
ssh hassio@192.168.1.10
```

Заработало — телевизор больше не нужен.

## Этап 5. Всё остальное — командами

```
1. Ежедневные резервные копии — ДО всего остального
2. recorder с исключениями (раздел 7)
3. git init в /config
4. Донгл: подключить, закрепить адрес, проверить прошивку
5. Mosquitto → Zigbee2MQTT
6. Устройства: сначала розетки и реле, потом датчики
7. Matter Server → лампы YNDX
8. HACS
9. LocalTuya (форк xZetsubou)
10. yandex_smart_home, YandexStation
11. ha-mcp — режим только чтения
12. AmneziaWG до KZ-сервера
13. Проверить восстановление из копии
```

# 7. Конфигурации

## recorder — настроить сразу

`/config/configuration.yaml`:

```yaml
recorder:
  purge_keep_days: 10
  commit_interval: 30
  exclude:
    domains:
      - updater
      - automation
    entity_globs:
      - sensor.*_linkquality
      - sensor.*_rssi
      - sensor.*_last_seen
      - sensor.*_update_available
    entities:
      - sun.sun
```

По умолчанию Home Assistant пишет каждое изменение каждого датчика. Розетки
с замером мощности шлют данные каждые несколько секунд. Без исключений база
вырастает до нескольких гигабайт за пару месяцев, интерфейс тормозит,
SSD без буфера изнашивается.

## Zigbee2MQTT

```yaml
mqtt:
  server: mqtt://core-mosquitto
  user: mqtt_user
  password: "ПАРОЛЬ_ИЗ_НАСТРОЕК_MOSQUITTO"

serial:
  # По USB:
  port: /dev/serial/by-id/...
  # По Ethernet:
  # port: tcp://192.168.1.11:6638
  adapter: ember
  baudrate: 115200
  rtscts: false

homeassistant:
  enabled: true

frontend:
  enabled: true
  port: 8099

advanced:
  log_level: info
  network_key: GENERATE
  pan_id: GENERATE
  channel: 25
```

**`adapter: ember` — критично.** Донгл на Silicon Labs EFR32MG24. Устаревшее `ezsp`
и тип `zstack` (от старого Dongle Plus) приведут к тому, что Zigbee2MQTT не запустится.
Самая частая ошибка с этим устройством.

**`rtscts: false`** — по официальной документации SONOFF.

**Канал 25** — минимальное пересечение с Wi-Fi 2.4 ГГц, где 13 устройств.

**Перед привязкой устройств проверить прошивку** в веб-консоли донгла:
для `ember` нужен EmberZNet ≥ 7.4.

## Порядок привязки Zigbee

**Сначала устройства с постоянным питанием, потом батарейные.**

Розетки и реле работают ретрансляторами и строят сеть. Датчики только принимают.
Подключите датчики первыми — они свяжутся напрямую с координатором через всю
квартиру и будут отваливаться.

```
Сначала: реле HOMMYN, розетки Tuya, реле без нейтрали, диммер, проводные выключатели
Потом:   датчики температуры, датчики протечки, беспроводные выключатели, кнопки
```

Подключать **по одному**, сразу проверяя, что устройство появилось с рабочими
кнопками. Вести табличку: устройство, модель в Z2M, работает или нет.

# 8. Безопасность AI-слоя

Формулировки уточнены после экспертного разбора — первые были завышены.

**Что НЕ работает:**

- «Отдельный пользователь без прав администратора» **не защищает**: правка
  автоматизаций идёт через конфигурационный API, требующий администратора.
  Включили запись — токен административный.
- «Список открытых сущностей» ограничивает **только** Assist API (YandexGPT,
  встроенный MCP). Для ha-mcp неверно: он работает через REST и WebSocket, видит всё.

**Что работает:**

```
1. Ничего опасного для жизни и имущества не отдавать модели вообще.
   В списке устройств нет замков, ворот и отопления — так и оставить.
   Максимальный ущерб при худшем раскладе: помигал свет.

2. Метка на всех автоматизациях от модели + один переключатель,
   отключающий их разом.

3. mode: single на каждой автоматизации от модели.
   Реле без нейтрали и диммер — самое хрупкое железо в доме,
   зацикливание с 50 переключениями в минуту их убьёт.

4. Запретить политикой ha-mcp: перезапуск Home Assistant,
   перезагрузку интеграций, инструменты Zigbee2MQTT и MQTT.

5. Режим только чтения, пока восстановление из копии
   не проверено хотя бы раз на практике.

6. git init в /config, коммит раз в сутки.

7. ha-mcp — только внутри локальной сети и туннеля.
   Его адрес с секретной строкой равносилен административному токену.
```

**Самая вероятная беда — не атака, а несчастный случай:** модель пишет
автоматизацию с триггером без целевого состояния, или две начинают вызывать
друг друга. Пункты 2 и 3 важнее всей защиты от злоумышленников.

# 9. Известные слабые места

**Почти весь дополнительный слой — проекты сообщества:** ha-mcp, YandexGPT,
LocalTuya, YandexStation, yandex_smart_home. Часть работает через
недокументированные API Яндекса. Официальны только ядро Home Assistant,
Zigbee2MQTT, Mosquitto.

**LocalTuya — слабейшее звено.** Оригинальный проект заброшен, живёт форк.
Ключи добываются через кабинет разработчика Tuya — процедура болезненная.
**Вывод: новые устройства покупать в версии Zigbee, а не Wi-Fi.**

**Донгл в статусе «не рекомендуется» у Zigbee2MQTT** с января 2026 —
нестабильность по Ethernet. Держать прошивку свежей, USB как запасной путь.
Резервная копия перед каждым обновлением Zigbee2MQTT: связка `ember` + прошивка —
главный источник поломок последних лет.

**У Home Assistant не будет обхода блокировок.** VPN-клиент работает под Windows,
после установки его не станет. HAOS пойдёт в интернет напрямую через Акадо:
Яндекс работает, обновления HA обычно доступны, **GitHub для HACS бывает
нестабилен**.

# 11. Команды

**Установка системы командами не делается** — записать флешку, BIOS, загрузка
делаются руками. Командная строка появляется после того, как Home Assistant
поднялся и включено дополнение SSH.

## Подключиться

```powershell
ssh hassio@192.168.1.10
```

## Осмотреться

```bash
ha core info
ha os info
ha network info
```

## Резервная копия — первым делом

```bash
ha backups new --name "chistaya-sistema"
ha backups list
```

## Правка конфигурации

```bash
cd /config
cp configuration.yaml configuration.yaml.backup
nano configuration.yaml
ha core check          # ОБЯЗАТЕЛЬНО до перезапуска
ha core restart
```

`ha core check` покажет ошибку синтаксиса. Перезапуск с битым конфигом
оставит систему лежать.

## Git

```bash
cd /config
git init && git add . && git commit -m "Исходное состояние"
```

Дальше после каждого изменения:
```bash
cd /config && git add . && git commit -m "что сделано"
```

```bash
ha addons list
ha addons install core_mosquitto

ha addons info core_mosquitto
```

# 12. Ошибки, допущенные в этом проекте

Полезно знать, чтобы не повторить. Владелец поймал шесть неверных утверждений.

| # | Неверно | Верно | Урок |
|---|---|---|---|
| 1 | Windows + Hyper-V как платформа | HAOS на голое железо | Сложность выбиралась, а потом обосновывалась обвязкой вокруг неё |
| 2 | Cloudflare, Tailscale, Nabu Casa для внешнего доступа | Свой VPS + AmneziaWG | Иностранные сервисы без проверки доступности из России |
| 3 | Telegram как ежедневный интерфейс | Заблокирован, исключён | То же самое, четвёртый раз подряд |
| 4 | `adapter: ezsp`, чип EFR32MG21 | `adapter: ember`, EFR32MG24 | Zigbee2MQTT не запустился бы |
| 5 | «У донгла нет Wi-Fi» | Есть, включая точку доступа | Утверждение без проверки |
| 6 | Proxmox ради «управляемости через SSH» | HAOS тоже управляем | Рационализация, повтор ошибки №1 |

**Общий узор:** иностранные сервисы предлагались без проверки доступности из России,
а сложность выбиралась и потом обосновывалась. **Проверяйте доступность до того,
как предлагать. Отличайте проверенное от предполагаемого.**
