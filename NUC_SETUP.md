| CPU | Intel Core i5-8259U @ 2.30GHz (4 ядра / 8 потоков, Coffee Lake-U, 28W TDP) | ✅ **Избыточно.** HA требует 2 ядра. Запас ×4 |

### 1.2 Идентификация модели

`i5-8259U` + форм-фактор NUC → почти наверняка **Intel NUC8i5BEH** или **NUC8i5BEK**.

| Модель | Накопители | LAN | USB |
|--------|-----------|-----|-----|
| NUC8i5BEH (высокий корпус) | M.2 NVMe + 2.5" SATA | 1× GbE (i219-V) | 4× USB 3.1 + 2× USB 2.0 (внутр.) |
| NUC8i5BEK (низкий корпус) | Только M.2 NVMe | 1× GbE (i219-V) | 4× USB 3.1 |

> **Нужно уточнить:** объём и тип накопителя. Скрипт `00-audit-system.ps1` соберёт эти данные автоматически.

### 1.3 Ключевой вывод по железу

**Железо избыточно для Home Assistant.** Это открывает возможность запустить HA в виртуальной машине и сохранить Windows для:
- МойАссистент (удалённый доступ, уже привычен)
- Резервных задач (файловый сервер, торренты, Plex и т.п.)

## 2. Архитектурное решение: три варианта

### Сравнение

| Критерий | А. HAOS bare metal | **Б. Windows + Hyper-V + HAOS VM** ⭐ | В. Proxmox + VM |
|----------|-------------------|--------------------------------------|-----------------|
| Windows сохраняется | ❌ Стирается | ✅ Да | ❌ Стирается |
| МойАссистент | ❌ Не работает | ✅ Работает как сейчас | ⚠️ Только Linux-версия |
| Производительность HA | 100% | ~92% | ~97% |
| Сложность установки | Средняя | **Низкая (скриптуется)** | Высокая |
| Автоматизация установки | Ручная (BIOS, USB) | ✅ **PowerShell — 1 команда** | Ручная |
| Риск от Windows Update | — | ⚠️ Перезагрузки (решаемо) | — |
| Снапшоты всей системы | ❌ | ✅ Checkpoint | ✅ |
| Откат при ошибке | Переустановка | ✅ Удалить VM | Удалить VM |

### ⭐ Рекомендация: Вариант Б — Windows 11 Pro + Hyper-V + HAOS VM

**Почему:**

1. **Максимальная автоматизация** — вся установка одним PowerShell-скриптом, без USB-флешек, BIOS и физического присутствия. Это прямо соответствует вашему требованию «минимум ручных действий».
2. **МойАссистент остаётся** — вы уже умеете им пользоваться, ничего не меняется.
3. **Zigbee-координатор сетевой** — SONOFF Dongle Max PoE подключается по TCP, а не по USB. **Проброс USB в VM не нужен** — это снимает главный аргумент против виртуализации.
4. **Обратимость** — если не понравится, удаляете VM и ставите bare metal. Ничего не потеряно.
5. **Запас ресурсов** — 16 ГБ RAM позволяют отдать HA 4 ГБ и не заметить.

**Риски варианта Б и как их закрыть (заложено в скриптах):**

| Риск | Нейтрализация | Где реализовано |
|------|--------------|-----------------|
| Windows Update перезагрузит систему | Active Hours 24/7 + отложенные обновления на 30 дней + VM с автостартом | `01-prepare-windows.ps1` |
| NUC уходит в сон | Все режимы сна отключены, план питания High Performance | `01-prepare-windows.ps1` |
| VM не стартует после перезагрузки | `AutomaticStartAction = Start`, задержка 30 сек | `02-install-haos-vm.ps1` |
| Автоматические чекпоинты ломают HAOS | `AutomaticCheckpointsEnabled = $false` | `02-install-haos-vm.ps1` |
| Динамическая память вызывает OOM | Статические 4 ГБ | `02-install-haos-vm.ps1` |
| Потеря сети у VM | External vSwitch на физическом адаптере + `MacAddressSpoofing` | `02-install-haos-vm.ps1` |

## 4. Удалённый доступ — двухуровневая схема

Важно понимать: это **два разных канала**, и оба нужны.

| Канал | Что даёт | Когда нужен |
|-------|----------|-------------|
| **МойАссистент** (рабочий стол Windows) | Полный контроль над хостом: Hyper-V Manager, перезапуск VM, BIOS-уровень проблем | Когда HA сам недоступен |
| **Nabu Casa / браузер** (веб-интерфейс HA) | Управление умным домом, конфиги, логи, add-ons | Повседневная работа |

### 4.1 МойАссистент — на NUC ставим обязательно

**Да, ставить стоит.** Обоснование:
- У вас он уже есть на рабочем ноутбуке → знакомый интерфейс, ничего нового учить не надо
- На рабочем ПК **не нужны права администратора**, если использовать клиентскую часть
- Это ваш **аварийный канал**: если HAOS зависнет, через МойАссистент вы зайдёте в Hyper-V Manager и перезапустите VM

**Установка на NUC (Windows-версия):**
Скрипт `01-prepare-windows.ps1` подготовит систему, но **сам МойАссистент устанавливается вручную** — это единственный шаг, который нельзя автоматизировать (нужна регистрация/привязка устройства к вашему аккаунту).

Порядок:
1. Скачать Windows-версию с `мойассистент.рф/скачать`
2. Установить на NUC
3. Настроить **неконтролируемый доступ** (постоянный пароль) — чтобы подключаться без подтверждения на стороне NUC
4. Включить **автозапуск при старте Windows**
5. Записать ID устройства

> **Linux-версия не нужна** в варианте Б — хост остаётся Windows. Она понадобилась бы только при выборе варианта В (Proxmox).

### 4.2 Резервный канал — Windows RDP

На случай, если МойАссистент недоступен, скрипт включит штатный RDP (порт 3389, только для локальной сети). Подключение с рабочего ноутбука — встроенный `mstsc.exe`, установка не требуется.

Все скрипты лежат в `scripts/`. Запускать **от имени администратора** в PowerShell.

```powershell
# 0. Аудит — понять что за железо, ничего не меняет
.\00-audit-system.ps1

# 1. Подготовка Windows — питание, обновления, Hyper-V, RDP

# 4. Настроить автоматический health-check (опционально, но рекомендуется)
```

## 7. Оценка рисков — специфика NUC + Hyper-V

### Риск N1: Windows Update перезагружает систему ночью ⚠️ ВЫСОКИЙ

**Сценарий провала через 6 месяцев:** «Умный дом перестал работать в 3 ночи, свет не включился утром. Оказалось — Windows поставил обновление и перезагрузился, VM не поднялась.»

**Нейтрализация (в `01-prepare-windows.ps1`):**
- Active Hours расширены на максимум (18 часов)
- `DeferFeatureUpdatesPeriodInDays = 365`, `DeferQualityUpdatesPeriodInDays = 30`
- `NoAutoRebootWithLoggedOnUsers = 1`
- VM с `AutomaticStartAction = Start` — поднимется даже после внезапной перезагрузки
- Health-check каждые 15 минут поднимет VM, если она не запустилась

### Риск N2: NUC уходит в сон / гибернацию ⚠️ ВЫСОКИЙ

**Нейтрализация:** План питания High Performance, `powercfg /hibernate off`, все таймауты сна = 0, отключён USB selective suspend.

### Риск N3: Автоматические чекпоинты Hyper-V ломают HAOS ⚠️ СРЕДНИЙ

Hyper-V в Windows 11 **по умолчанию включает** автоматические чекпоинты для новых VM. Для HAOS это вредно: разрастается диск, возможна порча БД recorder.

**Нейтрализация:** `Set-VM -AutomaticCheckpointsEnabled $false` в скрипте создания.

### Риск N4: Динамическая память вызывает нехватку у HAOS ⚠️ СРЕДНИЙ

**Нейтрализация:** `-StaticMemory` 4096 МБ. HAOS плохо переносит balloon-драйвер Hyper-V.

### Риск N5: VM получает случайный IP ⚠️ СРЕДНИЙ

**Нейтрализация:** Скрипт зафиксирует MAC-адрес VM (`-StaticMacAddress`) и выведет его — вы вносите его в DHCP-резервацию Eltex для `192.168.1.10`.

### Риск N6: Потеря доступа к NUC ⚠️ КРИТИЧЕСКИЙ

**Сценарий:** МойАссистент не запустился после перезагрузки, физически до NUC не добраться.

**Нейтрализация — три независимых канала:**
1. МойАссистент (основной)
2. Windows RDP на 3389 (резерв, включается скриптом)
3. Nabu Casa → веб-интерфейс HA (если проблема только в Windows-сессии, но VM жива)

### Риск N7: Диск NUC заполняется ⚠️ СРЕДНИЙ

VHDX растёт, HA-снапшоты копятся, Windows Update кэширует.

**Нейтрализация:** `04-setup-healthcheck.ps1` мониторит свободное место и пишет в лог при < 15 ГБ.

## 8. Что нужно уточнить перед стартом

Скрипт `00-audit-system.ps1` соберёт это автоматически, но заранее полезно знать:

- [ ] Объём накопителя (нужно ≥ 128 ГБ, комфортно ≥ 256 ГБ)
- [ ] Один или два накопителя (M.2 + SATA)
- [ ] Виртуализация включена в BIOS (VT-x) — обычно да, но проверим
- [ ] NUC подключён к Eltex по кабелю (не по WiFi — для стабильности)
- [ ] SONOFF Dongle Max уже подключён и доступен по `192.168.1.11`
