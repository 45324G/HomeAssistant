# ЧАСТЬ 1. Контекст для ассистента

## Что строим

Умный дом на Home Assistant. Владелец — новичок, живёт в России, ведёт проект через
AI-ассистентов и хочет, чтобы AI был операционным слоем, а он сам — заказчиком, а не
техником. В доме есть супруга, которая должна пользоваться голосом и не обязана
разбираться в технике.

## Что уже решено

| Решение | Обоснование |
|---|---|
| **Home Assistant OS на голое железо** | Windows стирается. Гипервизора нет — от Proxmox отказались после экспертного разбора |
| **Zigbee через SONOFF Dongle Max по Ethernet** | `adapter: ember`, `tcp://<ip>:6638`, канал 25 |
| **AI для создания автоматизаций через ha-mcp** | Не привязано к вендору, работает по MCP |
| **Голос через Алису со сценариями** | Колонки уже куплены |
| **Telegram-бот исключён** | Заблокирован в России |
| **AmneziaWG для удалённого доступа** | Обычный WireGuard в России глушится |

## Что НЕ решено — тесты ниже это закрывают

1. Тип и объём накопителя — от этого зависит, можно ли вообще ставить систему
2. Публичный IP или CGNAT — определяет всю схему удалённого доступа
3. Доступен ли Telegram — вернётся ли бот в план
4. Есть ли Bluetooth — нужен для CO2-монитора Qingping
5. Отдаёт ли камера поток RTSP
6. Версия прошивки Zigbee-донгла

## Оборудование

- Intel NUC8i5, i5-8259U, 16 ГБ, Windows 11 Pro 25H2, имя `DESKTOP-AGP4NF8`
- Роутер Eltex RG-1520G-Wax, провайдер Акадо
- SONOFF Dongle Max (EFR32MG24 + ESP32) — Ethernet, питание по USB
- ~30 устройств: Zigbee (Tuya, HOMMYN), Wi-Fi Tuya, Яндекс Станции Миди и Лайт 2,
  лампы YNDX-00551 (**Matter over Wi-Fi**), CO2-монитор Qingping, Wi-Fi камера

# ЧАСТЬ 3. Тесты

## Тест 1. Накопитель — самый важный

**Зачем:** если это жёсткий диск, а не SSD, ставить на него систему нельзя — Home Assistant
постоянно пишет в базу и убьёт механический диск. Понадобится купить SSD.

```powershell
Get-PhysicalDisk | Select-Object FriendlyName, MediaType, BusType,
  @{n='ГБ';e={[math]::Round($_.Size/1GB,0)}}, HealthStatus | Format-Table -AutoSize
```

**Как читать результат:**

| Что видим | Вердикт |
|---|---|
| `MediaType = SSD`, ≥ 250 ГБ | ✅ Ставим |
| `MediaType = SSD`, 120–250 ГБ | ⚠️ Хватит, но впритык |
| `MediaType = SSD`, < 120 ГБ | ⚠️ Мало — рекомендовать замену |
| `MediaType = HDD` | 🔴 **Стоп.** Нужен SSD, иначе строить нельзя |
| Два накопителя | ✅ Отлично — второй под резервные копии |

Дополнительно — модель накопителя для оценки качества:

```powershell
Get-Disk | Select-Object Number, FriendlyName, PartitionStyle,
  @{n='ГБ';e={[math]::Round($_.Size/1GB,0)}} | Format-Table -AutoSize
```

## Тест 2. Публичный IP или CGNAT — определяет схему доступа

**Зачем:** если провайдер не даёт публичный адрес, подключиться к дому снаружи напрямую
невозможно. Тогда нужен туннель через арендованный сервер. Это самая важная развилка.

```powershell
# Внешний адрес, который видит интернет
(Invoke-RestMethod -Uri "https://api.ipify.org?format=json").ip
```

```powershell
# Адрес шлюза в локальной сети
Get-NetRoute -DestinationPrefix "0.0.0.0/0" |
  Select-Object -ExpandProperty NextHop
```

**Дальше нужен владелец.** Попросите его:
1. Открыть веб-интерфейс роутера (адрес шлюза из команды выше)
2. Найти раздел со статусом WAN-подключения
3. Продиктовать WAN-адрес

**Как читать:**

| Что видим | Вердикт |
|---|---|
| WAN-адрес роутера = внешний адрес | ✅ Публичный IP. WireGuard на роутере |
| Адреса разные | 🔴 CGNAT. Нужен туннель через российский VPS |
| WAN начинается на `100.64.`–`100.127.` | 🔴 CGNAT однозначно |
| WAN начинается на `10.`, `192.168.`, `172.16.`–`172.31.` | 🔴 CGNAT |

> Сейчас NUC в рабочей сети — результат будет про офис. Тест надо повторить дома.
> Но если владелец может проверить домашний роутер с телефона — лучше сделать это сразу.

## Тест 3. Доступен ли Telegram

**Зачем:** план предполагает, что Telegram в России заблокирован, и убирает бота
из архитектуры. Проверяем.

```powershell
Test-NetConnection -ComputerName api.telegram.org -Port 443 -InformationLevel Detailed
```

```powershell
try {
  $r = Invoke-WebRequest -Uri "https://api.telegram.org" -TimeoutSec 15 -UseBasicParsing
  "Ответ получен: HTTP $($r.StatusCode)"
} catch {
  "Недоступен: $($_.Exception.Message)"
}
```

**Как читать:**

| Что видим | Вердикт |
|---|---|
| Соединение установлено, HTTP-ответ есть | ✅ Бот возвращается в план как дополнительный канал |
| Таймаут или сброс соединения | ✅ Подтверждает блокировку — плана не меняем |

> Важно: рабочая сеть может иметь свои фильтры. Проверить надо и дома тоже.

## Тест 4. Bluetooth

**Зачем:** CO2-монитор Qingping работает по Bluetooth. Home Assistant на голом железе
увидит встроенный Bluetooth напрямую.

```powershell
Get-PnpDevice -Class Bluetooth -ErrorAction SilentlyContinue |
  Select-Object Status, FriendlyName | Format-Table -AutoSize
```

| Что видим | Вердикт |
|---|---|
| Устройства со статусом `OK` | ✅ Bluetooth есть, Qingping подключится |
| Пусто | ⚠️ Понадобится USB-адаптер Bluetooth (~500 ₽) |

## Тест 5. Сеть и MAC-адрес

**Зачем:** MAC нужен, чтобы закрепить за Home Assistant постоянный адрес на роутере.

```powershell
Get-NetAdapter | Where-Object Status -eq 'Up' |
  Select-Object Name, InterfaceDescription, MacAddress, LinkSpeed | Format-Table -AutoSize
```

```powershell
Get-NetIPConfiguration | Where-Object { $_.IPv4Address } |
  Select-Object InterfaceAlias, IPv4Address, IPv4DefaultGateway
```

**Записать MAC проводного адаптера** — он понадобится дома при настройке роутера.

## Тест 6. Скорость интернета

**Зачем:** образ Home Assistant ~1.5 ГБ. Если в офисе быстро — скачать здесь.

```powershell
$sw = [System.Diagnostics.Stopwatch]::StartNew()
Invoke-WebRequest -Uri "https://speed.cloudflare.com/__down?bytes=25000000" `
  -OutFile "$env:TEMP\spd.bin" -UseBasicParsing
$sw.Stop()
"Скорость: {0:N1} Мбит/с" -f (25*8/$sw.Elapsed.TotalSeconds)
Remove-Item "$env:TEMP\spd.bin" -Force
```

## Тест 7. Общая информация о системе

```powershell
$cs = Get-CimInstance Win32_ComputerSystem
$os = Get-CimInstance Win32_OperatingSystem
$bios = Get-CimInstance Win32_BIOS
[PSCustomObject]@{
  Модель      = "$($cs.Manufacturer) $($cs.Model)"
  BIOS        = "$($bios.SMBIOSBIOSVersion) от $($bios.ReleaseDate)"
  Процессор   = (Get-CimInstance Win32_Processor).Name.Trim()
  ОЗУ_ГБ      = [math]::Round($cs.TotalPhysicalMemory/1GB,1)
  ОС          = "$($os.Caption) сборка $($os.BuildNumber)"
} | Format-List
```

## Тест 8. Zigbee-донгл — только когда он в одной сети с NUC

**Пропустить, если донгл ещё не подключён к роутеру кабелем.**

```powershell
# Найти донгл в сети
$me = (Get-NetIPAddress -AddressFamily IPv4 |
       Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
       Select-Object -First 1).IPAddress
$base = $me -replace '\.\d+$',''
"Сканирую $base.0/24, ~15 секунд..."
$t = 1..254 | ForEach-Object { (New-Object Net.NetworkInformation.Ping).SendPingAsync("$base.$_",400) }
try { [Threading.Tasks.Task]::WaitAll($t,20000) | Out-Null } catch {}
$up = @($t | Where-Object { $_.Status -eq 'RanToCompletion' -and $_.Result.Status -eq 'Success' } |
        ForEach-Object { $_.Result.Address.ToString() })
foreach ($i in ($up | Sort-Object {[version]$_})) {
  $p = Test-NetConnection $i -Port 6638 -InformationLevel Quiet -WarningAction 0 -EA 0
  if ($p) { "НАЙДЕН ДОНГЛ: $i — порт 6638 открыт" }
}
```

Если найден — попросить владельца открыть `http://<адрес>` в браузере и продиктовать
**версию прошивки**. Для драйвера `ember` нужен EmberZNet не ниже 7.4.

# ЧАСТЬ 5. Решения, которые примут результаты

| Результат | Что меняется |
|---|---|
| Накопитель — HDD | 🔴 Купить SSD до начала. Иначе система умрёт за месяцы |
| Накопителя < 120 ГБ | Сократить хранение истории, копии только на внешний диск |
| Два накопителя | Второй сразу под резервные копии |
| CGNAT | Арендовать российский VPS (~200 ₽/мес), туннель изнутри наружу |
| Публичный IP | WireGuard прямо на роутере Eltex, VPS не нужен |
| Telegram работает | Бот возвращается как дополнительный канал (не основной) |
| Нет Bluetooth | Купить USB-адаптер для CO2-монитора |
| Прошивка донгла < 7.4 | Обновить **до** привязки устройств, не после |

# ЧАСТЬ 6. Открытый вопрос для владельца

Требует решения человека, тестами не закрывается.

## Куда вести лампы YNDX-00551

Лампы работают по **Matter over Wi-Fi**. Управление локальное в обоих вариантах —
но контроллер разный, и одновременно в двух системах Яндекс их держать не даёт.

| | Лампы у Яндекса | Лампы в Home Assistant |
|---|---|---|
| Управление | Локальное, через Станцию | Локальное, через HA |
| Интернет пропал | ✅ Алиса управляет голосом | ❌ Алиса их не видит |
| Home Assistant сломался | ✅ Работают | ❌ Не работают |
| Чужой ретранслятор в пути | Да, когда командует HA | Нет никогда |
| Свои фразы без интернета | ❌ Не работают | ❌ Не работают |
| Выключатель на стене | ✅ Всегда | ✅ Всегда |

**Рекомендация:** вести в Home Assistant. Убирается зависимость от стороннего
ретранслятора в ежедневном пути. Теряется только голосовое управление в момент
обрыва интернета — но тогда и свои фразы всё равно не работают, а выключатель работает.

**Контраргумент:** если обрывы интернета частые, вариант с Яндексом даёт супруге
работающий голос в эти моменты.

Решение за владельцем.

# ЧАСТЬ 7. После отчёта

Когда отчёт готов — **остановиться и показать владельцу**. Не устанавливать ничего.

Дальнейший порядок (уже дома, с телевизором вместо монитора):

```
1. Скачать образ haos_generic-x86-64 и записать флешку
2. BIOS: UEFI, Secure Boot выключить, автовключение после пропадания питания
3. Загрузиться с флешки, установить HAOS на внутренний накопитель
4. Открыть http://homeassistant.local:8123
5. Дальше — только браузер
```

**Как только владелец загрузится с флешки — удалённый доступ исчезнет навсегда.**
Всё, что не проверено сейчас, проверяется только с подключённым телевизором.
