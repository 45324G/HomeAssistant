# Промпт для развертывания Home Assistant на NUC

> Готовый промпт для AI-агента (Claude Code / другой ассистент), запущенного **на самом NUC**
> или подключённого к нему. Скопируйте блок ниже целиком.

---

## Как использовать

1. Подключитесь к NUC через МойАссистент
2. Откройте на NUC PowerShell **от имени администратора**
3. Скачайте репозиторий:
   ```powershell
   cd C:\
   git clone https://github.com/45324G/HomeAssistant.git
   cd HomeAssistant\scripts
   ```
   *(если git не установлен — скачайте ZIP с GitHub и распакуйте в `C:\HomeAssistant`)*
4. Дайте AI-ассистенту промпт из блока ниже

---

## ПРОМПТ (копировать целиком)

````text
Ты работаешь на Intel NUC (DESKTOP-AGP4NF8) под Windows 11 Pro 25H2.
Железо: Intel Core i5-8259U (4 ядра / 8 потоков), 16 ГБ RAM.
Задача: развернуть Home Assistant OS в Hyper-V с максимальной автоматизацией.

КОНТЕКСТ ИНФРАСТРУКТУРЫ
- Роутер: Eltex RG-1520G-Wax, веб-интерфейс на 192.168.1.1 (или 192.168.0.1)
- Провайдер: Акадо, подключение по кабелю
- Zigbee-координатор: SONOFF Dongle Max (Dongle-M). Умеет три режима связи:
  Ethernet, Wi-Fi и USB. ИСПОЛЬЗУЕТСЯ ETHERNET (Wi-Fi не рекомендован
  официальной документацией Z2M: serial-протокол не переносит потери пакетов).
  Питание: USB Type-C 5V/1A от NUC либо PoE 48V.
  Целевой IP 192.168.1.11, TCP-порт 6638, адрес для Z2M: tcp://192.168.1.11:6638
- Целевой IP Home Assistant: 192.168.1.10
- Удалённый доступ к NUC: МойАссистент (мойассистент.рф) + RDP как резерв

ВАЖНО: Zigbee-донгл подключается ПО СЕТИ (Ethernet), поэтому проброс USB
в VM НЕ НУЖЕН — Hyper-V его и не умеет. Это ключевая причина, почему
виртуализация здесь безопасна. USB-кабель используется ТОЛЬКО для питания.

ЖЁСТКИЕ ТРЕБОВАНИЯ К РЕШЕНИЮ
1. Windows 11 Pro НЕ стирать — на нём остаётся МойАссистент
2. HAOS ставить как VM Generation 2 в Hyper-V
3. Secure Boot в VM обязательно ВЫКЛЮЧЕН (HAOS не подписан ключами Microsoft)
4. Память VM — СТАТИЧЕСКАЯ 4 ГБ (HAOS плохо работает с balloon-драйвером)
5. Автоматические чекпоинты Hyper-V ОТКЛЮЧИТЬ (разрастание диска, порча БД recorder)
6. VM с автозапуском при старте Windows, задержка 30 сек
7. MAC-адрес VM зафиксировать (нужен для DHCP-резервации на Eltex)
8. Максимум автоматизации — пользователь должен делать минимум ручных действий

ПОРЯДОК ВЫПОЛНЕНИЯ

Этап 0 — Аудит
  Запусти: .\00-audit-system.ps1
  Прочитай audit-report.txt.
  Проверь и доложи:
    - объём и тип накопителя (нужно ≥ 40 ГБ свободно)
    - включена ли VT-x в BIOS
    - редакция Windows (должна быть Pro/Enterprise — иначе Hyper-V недоступен)
    - подключён ли NUC кабелем (не WiFi)
    - отвечает ли 192.168.1.11 (донгл)
  Если есть блокеры со статусом FAIL — остановись и объясни, что делать.

Этап 1 — Подготовка Windows
  Запусти: .\01-prepare-windows.ps1
  Скрипт отключит сон/гибернацию, отложит Windows Update, включит RDP и Hyper-V.
  После него ОБЯЗАТЕЛЬНА перезагрузка.
  Скажи пользователю перезагрузиться и вернуться к тебе.

Этап 2 — МойАссистент (ручной шаг пользователя)
  Это единственное, что нельзя автоматизировать — нужна привязка к аккаунту.
  Дай пользователю инструкцию:
    1. Скачать Windows-версию с мойассистент.рф
    2. Установить на NUC
    3. Настроить постоянный пароль (неконтролируемый доступ) —
       чтобы подключаться без подтверждения на стороне NUC
    4. Включить автозапуск при старте Windows
    5. Записать ID устройства
  Дождись подтверждения, что установлено.

Этап 3 — Создание VM
  Запусти: .\02-install-haos-vm.ps1
  Скрипт сам скачает последний HAOS, распакует, создаст vSwitch и VM, запустит её.
  Из вывода забери и запиши: MAC-адрес VM, IP-адрес, версию HAOS.
  Если IP не определился — найди VM в DHCP-таблице роутера по MAC.

Этап 4 — Фиксация IP на роутере (шаг пользователя)
  Дай инструкцию: зайти на 192.168.1.1, раздел LAN -> DHCP -> Резервирование,
  привязать MAC виртуальной машины к 192.168.1.10.
  Затем перезапустить VM: Restart-VM -Name HomeAssistant
  Проверь, что HA доступен на 192.168.1.10:8123.

Этап 5 — Проверка
  Запусти: .\03-verify.ps1
  Разбери каждый FAIL и WARN. Исправь то, что исправимо командами.
  Доложи итог: сколько PASS / WARN / FAIL.

Этап 6 — Автомониторинг
  Запусти: .\04-setup-healthcheck.ps1
  Убедись, что задача HA-VM-HealthCheck создана и первый прогон записал лог.

Этап 7 — Первичная настройка Home Assistant (через браузер)
  Скажи пользователю открыть http://192.168.1.10:8123 и создать аккаунт админа.
  Часовой пояс: Europe/Moscow.
  Затем помоги установить add-ons в таком порядке:
    1. Mosquitto broker      — запустить, включить watchdog и автозапуск
    2. File editor           — для правки конфигов
    3. Advanced SSH & Web Terminal — задать пароль, включить порт 22
    4. Zigbee2MQTT           — установить, но НЕ запускать до настройки

  Конфиг Zigbee2MQTT (/addon_configs/zigbee2mqtt/configuration.yaml):
    mqtt:
      server: mqtt://core-mosquitto
      user: mqtt_user
      password: <пароль из настроек Mosquitto>
    serial:
      port: tcp://192.168.1.11:6638
      adapter: ember
    homeassistant:
      enabled: true
    frontend:
      enabled: true
      port: 8099
    advanced:
      log_level: info
      network_key: GENERATE
      pan_id: GENERATE
      channel: 25

  КРИТИЧНО: adapter именно 'ember'. SONOFF Dongle Max построен на чипах
  Silicon Labs EFR32MG24 (радио) + ESP32-D0WD-R2 (сеть). В Zigbee2MQTT для
  таких адаптеров используется драйвер 'ember'. Устаревшее имя 'ezsp' и
  тип 'zstack' (от Dongle Plus на CC2652P) приведут к тому, что Z2M не стартует.
  Вместо IP можно указать имя: tcp://Dongle-M.local:6638

  Канал 25 выбран потому, что минимально перекрывается с WiFi 2.4 ГГц
  (каналы WiFi 1/6/11 перекрывают Zigbee 11–22).

Этап 8 — Резервное копирование
  Настрой в HA: Settings -> System -> Backups -> Automatic backups
    Frequency: Daily, Copies to keep: 7
  Помоги установить HACS, затем add-on Google Drive Backup для копий в облако.

ПРАВИЛА РАБОТЫ
- Перед каждым шагом коротко объясняй, что сейчас произойдёт и зачем
- После каждого скрипта показывай ключевые строки вывода, не весь лог
- Если скрипт упал — покажи точную ошибку и предложи исправление,
  не переходи к следующему этапу
- Ничего не удаляй без явного подтверждения пользователя
- Все скрипты идемпотентны: повторный запуск безопасен
- Пиши по-русски

ЧТО НЕ ДЕЛАТЬ
- Не пробрасывай USB в VM — донгл сетевой, это не нужно
- Не включай динамическую память для VM
- Не оставляй Secure Boot включённым
- Не создавай чекпоинты VM «на всякий случай» — используй бэкапы самого HA
- Не открывай RDP или порт 8123 наружу в интернет —
  для внешнего доступа используется Nabu Casa
````

## Итоговая карта ручных действий

После всей автоматизации от вас требуется ровно это:

| # | Действие | Время | Почему нельзя автоматизировать |
|---|----------|-------|-------------------------------|
| 1 | Запустить 4 скрипта по очереди | 5 мин | — (можно и одной командой) |
| 2 | Одна перезагрузка после Hyper-V | 2 мин | Требование Windows |
| 3 | Установить МойАссистент | 10 мин | Привязка к личному аккаунту |
| 4 | Резервация IP на роутере Eltex | 5 мин | Нет API у роутера |
| 5 | Создать аккаунт админа в HA | 3 мин | Пароль знаете только вы |
| 6 | Установить add-ons через веб-интерфейс | 20 мин | Supervisor API требует токен |
| 7 | Сопряжение Zigbee-устройств | 60–90 мин | Физическое нажатие кнопок |

**Итого: ~2.5 часа**, из них 90 минут — физическое сопряжение устройств,
которое в принципе нельзя автоматизировать.

Для сравнения, изначальный план с ноутбуком и загрузочной флешкой требовал
~12–20 часов и физического присутствия на большинстве этапов.

## Однострочный запуск всей автоматизации

Если хотите пропустить пошаговый разбор — в PowerShell от администратора:

```powershell
cd C:\HomeAssistant\scripts
.\00-audit-system.ps1
.\01-prepare-windows.ps1     # -> перезагрузка
# после перезагрузки и установки МойАссистент:
.\02-install-haos-vm.ps1
.\03-verify.ps1
.\04-setup-healthcheck.ps1
```

## Если что-то пошло не так

| Симптом | Команда диагностики |
|---------|--------------------|
| VM не создаётся | `.\00-audit-system.ps1` — проверить VT-x и место на диске |
| VM создана, но не грузится | `vmconnect.exe localhost HomeAssistant` — увидеть экран загрузки |
| HAOS грузится, но нет сети | `Get-VMSwitch` — проверить что External-коммутатор на нужном адаптере |
| Не знаю IP виртуалки | `(Get-VMNetworkAdapter -VMName HomeAssistant).IPAddresses` |
| Zigbee2MQTT не стартует | Проверить `adapter: ember` и `Test-NetConnection 192.168.1.11 -Port 6638` |
| Всё сломалось, начать заново | `.\02-install-haos-vm.ps1` → ввести `DELETE` при запросе |

Быстрый статус в любой момент:
```powershell
powershell -File C:\HyperV\healthcheck\ha-status.ps1
```
