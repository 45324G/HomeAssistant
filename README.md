### Ключевые технологические решения

| Слой | Технология | Обоснование |
|------|-----------|-------------|
| ОС для HA | Home Assistant OS (HAOS) | Официальный путь, supervisor, add-ons, снапшоты |
| Zigbee координатор | SONOFF Dongle Max PoE → TCP | Размещение отдельно от ноутбука для лучшего покрытия |
| Zigbee интеграция | Zigbee2MQTT + Mosquitto | Лучшая совместимость с Tuya/HOMMYN устройствами |
| WiFi Tuya устройства | LocalTuya | Локальное управление без облака |
| Голосовое управление | Yandex Smart Home (YSH) интеграция | Сохранение Алисы + добавление HA |
| Бэкап | Автоматические снапшоты HA + внешний диск | Восстановление за 10 минут |

### 2.2.1 Архитектура голосового управления через Алису

**Концепция:** Алиса (Станция Миди) управляет устройствами через HA — таким образом все устройства в HA становятся доступны через голос, включая те, которые Яндекс напрямую не поддерживает (Tuya, HOMMYN и пр.).

```
Пользователь: "Алиса, включи свет в спальне"
        │
        ▼
[Яндекс Станция Миди]
        │ облако Яндекса
        ▼
[Яндекс Навык "Умный дом" / YSH skill]
        │ HTTPS webhook → HA
        ▼
[Home Assistant] → light.turn_on → [Zigbee лампа / Tuya розетка / ...]
```

**Что нужно настроить для голосового управления:**

1. **YSH интеграция в HA** (HACS) — экспортирует устройства HA в Яндекс аккаунт
2. **Яндекс Диалоги / Навык** — связывает аккаунт Яндекса с HA
3. **Внешний доступ к HA** — Яндекс должен "достучаться" до вашего HA из интернета

**Три варианта внешнего доступа (от простого к сложному):**

| Вариант | Сложность | Стоимость | Надёжность |
|---------|-----------|-----------|-----------|
| **Nabu Casa** (облако HA) | Минимальная | ~$65/год | Высокая |
| **Ngrok / Cloudflare Tunnel** | Низкая | Бесплатно | Средняя |
| **Домашний сервер + DynDNS** | Средняя | Бесплатно | Высокая |

> **Рекомендация:** Для начала использовать **Nabu Casa** — одна кнопка, всё работает сразу. После стабилизации системы можно перейти на Cloudflare Tunnel (бесплатно, надёжнее Ngrok).

**Настройка Nabu Casa:**
1. В HA: `Settings → Home Assistant Cloud → Sign up`
2. Создайте аккаунт на nabu.casa ($6.5/месяц)
3. После активации — Remote Access включается автоматически
4. YSH интеграция автоматически получит внешний URL от Nabu Casa

**Настройка через Cloudflare Tunnel (бесплатный вариант):**
```bash
# В HA: Settings → Add-ons → Cloudflare Tunnel add-on (через HACS)
# Или вручную через Cloudflare Zero Trust Dashboard
# Туннель: homeassistant.YOURDOMAIN.com → http://192.168.1.10:8123
```

> **Факт-чек Станция Миди:** Яндекс Станция Миди (YNDX-00054 / Midi) поддерживает все голосовые команды Алисы включая управление умным домом. Для связи с HA используется тот же механизм YSH навыка, что и для других Станций. Никакого специального конфига для Миди не нужно — достаточно одной YSH интеграции на аккаунт Яндекса.

> **Факт-чек Qingping CO2 монитор:** Qingping Air Monitor Lite и аналогичные модели поддерживают протокол HomeKit (через HomeKit Controller интеграцию в HA — встроенная, без HACS) или через фирменное облако Qingping+. **Рекомендуется HomeKit путь** — он локальный и не требует облака. Устройство отображает CO₂ (ppm), температуру, влажность, PM2.5 (в зависимости от модели). Проверьте: если на упаковке есть значок HomeKit — интеграция через HomeKit Controller.

> **Факт-чек по HOMMYN:** Модули HOMMYN HDN/WFN-02-01 используют протокол Tuya (проверено по FCC/CE документации и отзывам пользователей на 4PDA). LocalTuya должен работать после получения Device ID и Local Key через Tuya Developer Console.

> **Факт-чек по MAUNFELD:** По состоянию на июнь 2026, официальной HA интеграции для MAUNFELD нет. Альтернатива: если машина поддерживает IFTTT или имеет открытое API — использовать REST команды.

> **Факт-чек по Cootli CI-OIDWF242:** Камера использует протокол Tuya Smart Life. Видеопоток возможен через RTSP (порт 554) после получения credentials. В HA добавляется как Generic Camera.

### 2.4 Диммер Arlight SMART-MINI-DIM-SET

**Проблема:** Это инфракрасный/RF пульт управления диммером без WiFi/Zigbee.

**Решение:** Добавить IR-blaster (например, Broadlink RM4 Mini, ~1500 руб.) и обучить его командам ПДУ. Broadlink полностью поддерживается Home Assistant.

## 3. Сетевая топология

### 3.0 Роутер: Eltex RG-1520G-Wax

**Характеристики (проверено по официальному datasheet Eltex):**
- 4× GbE LAN порта + 1× GbE WAN
- WiFi 6 (802.11ax), двухдиапазонный: 2.4GHz + 5GHz
- Easy Mesh поддержка
- USB 2.0
- **PoE на LAN портах: НЕТ** (стандартный домашний роутер без PoE)
- Провайдер: Акадо (подключение WAN по DHCP или PPPoE)

### 3.1 Решение: Один LAN порт на ноутбуке — не проблема

**Ситуация:** ASUS N551VW имеет один порт RJ-45 (GbE). Но Eltex RG-1520G-Wax имеет **4 LAN порта** — внешний switch не нужен.

**Итоговая схема подключения:**

```
Провайдер Акадо
      │ (коаксиал/витая пара)
      ▼
[Eltex RG-1520G-Wax]
  WAN: ──── Провайдер Акадо
  LAN 1: ── ASUS N551VW (Home Assistant)      → 192.168.1.10
  LAN 2: ── PoE Injector (Data IN)
             PoE Injector (Data+Power OUT) ── SONOFF Dongle Max PoE → 192.168.1.11
  LAN 3: ── свободен (резерв)
  LAN 4: ── свободен (резерв)
  WiFi 2.4GHz: все IoT устройства
  WiFi 5GHz: телефоны, ноутбуки
```

**Необходимое доп. оборудование:**
- PoE Injector: TP-Link TL-POE150S (802.3af, 15.4W, ~600 руб.) — совместим с SONOFF Dongle Max
- 2× кабель Ethernet Cat5e/Cat6 (~200 руб.)

> **Switch НЕ нужен** — 4 LAN порта Eltex достаточно.

> **Факт-чек Eltex RG-1520G-Wax:** LAN порты работают как обычный коммутатор без PoE. Для питания SONOFF Dongle Max обязателен PoE инжектор. Потребление Dongle Max — около 2.5W, TL-POE150S с запасом покрывает это.

### 3.2 IP-адресация (рекомендуемая)

```
Подсеть: 192.168.1.0/24
Роутер/Шлюз: 192.168.1.1
DNS: 192.168.1.1 (локальный) / 8.8.8.8 (резервный)

Статические IP (назначить через DHCP Reservation на роутере):
  Home Assistant (ASUS N551VW):     192.168.1.10
  SONOFF Dongle Max PoE:            192.168.1.11
  
DHCP диапазон для остальных:       192.168.1.100–254
```

## 4. Пошаговая установка

### Этап 0: Подготовка

#### 0.1 Необходимые компоненты

- [ ] USB флешка ≥ 16GB (для установки HAOS) — Class 10 / USB 3.0
- [ ] USB флешка ≥ 32GB или внешний SSD (для работы HA — надёжнее HDD ноутбука)
- [ ] TP-Link TL-SG105 switch
- [ ] TP-Link TL-POE150S PoE инжектор
- [ ] 2× кабель Ethernet Cat5e/Cat6
- [ ] Balena Etcher (для записи образа)

> **Важно:** НЕ устанавливайте HA на встроенный HDD ноутбука — это основной источник отказов (HDD изнашивается, случайное обновление Windows сломает всё). Используйте отдельный USB SSD (Samsung T7 portable, ~3000 руб.).

#### 0.2 Проверка ASUS N551VW

ASUS N551VW характеристики (проверено):
- CPU: Intel Core i7-6700HQ / i5-6300HQ
- RAM: 8-16GB DDR4
- Встроенный WiFi: Intel Dual Band Wireless-AC 3165 (поддерживается в Linux)
- LAN: Realtek RTL8111H GbE
- USB: 3× USB 3.0

HA минимальные требования: 2GB RAM, 32GB storage, 2-ядерный CPU 2GHz.
N551VW превышает требования — проблем нет.

### Этап 1: Сетевая инфраструктура

#### 1.1 Подключение switch

```bash
# Физическое подключение:
Модем/Роутер LAN1 ──── [Switch порт 1 = Uplink]
[Switch порт 2] ──── ASUS N551VW (LAN)
[Switch порт 3] ──── PoE Injector (Data IN)
PoE Injector (Data+Power OUT) ──── SONOFF Dongle Max PoE (LAN)
```

#### 1.2 Настройка SONOFF Dongle Max PoE

1. Подключите Dongle Max к PoE инжектору
2. Подождите 30 секунд — загружается встроенный Linux
3. По умолчанию Dongle Max работает как DHCP клиент
4. Найдите его IP через интерфейс роутера (раздел DHCP leases)
5. Назначьте статический IP 192.168.1.11 через MAC reservation на роутере
6. Проверьте доступность: `ping 192.168.1.11`

> **Факт-чек SONOFF Dongle Max PoE:** Устройство поднимает ser2net на порту 6638 (по умолчанию). Zigbee2MQTT подключается по адресу `tcp://192.168.1.11:6638`. Это подтверждено официальной документацией SONOFF и обсуждениями на GitHub zigbee2mqtt/zigbee2mqtt.

### Этап 2: Установка Home Assistant OS

#### 2.1 Скачивание образа

1. Перейдите на [github.com/home-assistant/operating-system/releases](https://github.com/home-assistant/operating-system/releases)
2. Скачайте `haos_generic-x86-64-XX.X.img.xz` (для x86-64 ПК)
3. Проверьте SHA256 хеш файла (опубликован рядом с релизом)

#### 2.2 Запись образа

```bash
# Windows: используйте Balena Etcher (etcher.balena.io)
# Linux:
xz -d haos_generic-x86-64-XX.X.img.xz
sudo dd if=haos_generic-x86-64-XX.X.img of=/dev/sdX bs=4M status=progress
sudo sync

# Проверка после записи:
sudo fdisk -l /dev/sdX  # должны быть видны разделы HA
```

#### 2.3 Настройка BIOS ASUS N551VW

1. Включите ноутбук, нажмите `F2` для входа в BIOS
2. `Security → Secure Boot → Disabled`
3. `Boot → Boot Option Priorities → USB первым`
4. `Advanced → USB Configuration → USB Legacy Support = Enabled`
5. Сохраните и выйдите (`F10`)

#### 2.4 Первый запуск

1. Подключите USB с HAOS к ноутбуку
2. Подключите LAN кабель (к switch)
3. Включите ноутбук
4. HAOS загрузится и запустит установку (~3–5 минут)
5. На экране ноутбука появится IP адрес HA (или найдите его в роутере)
6. С другого устройства откройте `http://192.168.1.10:8123`
7. Пройдите мастер первоначальной настройки

> **Если HA устанавливается на встроенный диск ноутбука:**  
> На экране установщика выберите нужный диск. HAOS ПЕРЕЗАПИШЕТ весь диск без предупреждения. Убедитесь что выбрали правильный диск.

### Этап 3: Базовая конфигурация HA

#### 3.1 Установка обязательных Add-ons

В HA: `Settings → Add-ons → Add-on Store`

Установить в следующем порядке:

1. **Mosquitto broker** (официальный от Nabu Casa)
   - Установить → Start → Enable watchdog → Enable auto-update

2. **Zigbee2MQTT**
   - Установить → НЕ запускать (сначала настроить)

3. **File editor** или **VS Code** (для редактирования конфигов)
   - Установить → Start

4. **Advanced SSH & Web Terminal** (для диагностики)
   - Установить → Start
   - Установить пароль в настройках add-on

#### 3.2 Настройка Zigbee2MQTT

В File editor откройте `/addon_configs/zigbee2mqtt/configuration.yaml`:

```yaml
# /addon_configs/zigbee2mqtt/configuration.yaml
mqtt:
  server: mqtt://core-mosquitto
  user: mqtt_user          # создать в Mosquitto настройках
  password: YOUR_PASSWORD

serial:
  port: tcp://192.168.1.11:6638  # SONOFF Dongle Max PoE IP
  adapter: ember                  # для SONOFF Dongle Max (EFR32MG24)

homeassistant:
  enabled: true

frontend:
  enabled: true
  port: 8099

advanced:
  log_level: info
  network_key: GENERATE  # автогенерация при первом запуске
  pan_id: GENERATE
  channel: 25  # канал 25 — минимальное перекрытие с WiFi 2.4GHz
```

> **Факт-чек адаптер (ИСПРАВЛЕНО 2026-09-01):** SONOFF Dongle Max построен на двух чипах: **Silicon Labs EFR32MG24** (радио Zigbee/Thread) и **ESP32-D0WD-R2** (сеть и веб-консоль). Правильный тип адаптера в Zigbee2MQTT — **`ember`**. Ранее в этом документе было указано `ezsp` — это устаревшее название драйвера, в актуальных версиях Z2M используется `ember`. Тип `zstack` относится к старому ZBDONGLE-P на CC2652P и здесь не подходит.

> **Факт-чек канал 25:** WiFi 2.4GHz каналы 1, 6, 11 перекрываются с Zigbee каналами 11-22. Zigbee канал 25 имеет минимальное RF-перекрытие с WiFi. Рекомендован сообществом HA для смешанных окружений.

После настройки: запустить Zigbee2MQTT add-on.

**Шаг 2: Настройка внешнего доступа (обязательно!)**

Алиса обращается к вашему HA из интернета — без внешнего доступа голосовое управление работать не будет.

*Вариант А — Nabu Casa (самый простой):*
```
HA → Settings → Home Assistant Cloud → Create Account
```

После активации URL вида: `https://XXXX.ui.nabu.casa` — он используется в YSH.

*Вариант Б — Cloudflare Tunnel (бесплатно, надёжно):*

3. Создайте туннель в Cloudflare Zero Trust Dashboard → Networks → Tunnels
4. Укажите маршрут: `ha.YOURDOMAIN.ru` → `http://localhost:8123`
5. Результат: `https://ha.YOURDOMAIN.ru` — стабильный внешний адрес HA

**Шаг 3: Создание навыка в Яндекс Диалогах**

1. Откройте [dialogs.yandex.ru](https://dialogs.yandex.ru)
2. Создать диалог → Умный дом
3. Backend: ваш внешний URL HA + `/api/yandex_smart_home/v1.0`  
   Например: `https://ha.YOURDOMAIN.ru/api/yandex_smart_home/v1.0`
4. Сохраните — получите `Skill ID`

**Шаг 4: OAuth токен и привязка аккаунта**

В YSH интеграции HA выберите `Connection via cloud` (если Nabu Casa) или `Direct connection` и укажите:
- Внешний URL: `https://ha.YOURDOMAIN.ru`
- Skill ID из Яндекс Диалогов

1. Приложение Яндекс → Устройства → Добавить устройство

## 7. Оценка рисков — 6-месячный постмортем

> Анализ: "Прошло 6 месяцев — почему проект не удался?"

### Риск #1: Нестабильная работа координатора Zigbee ⚠️ ВЫСОКИЙ

**Симптомы провала:** Zigbee устройства периодически пропадают, перестают отвечать. Требуется перезапуск Zigbee2MQTT каждые несколько дней.

**Причины:**
- Интерференция от WiFi роутера (работают на одной частоте 2.4GHz)
- Неправильный Zigbee канал (перекрывается с WiFi)
- SONOFF Dongle Max слишком далеко от устройств / мало роутерных устройств в mesh

**Превентивные меры:**
- ✅ Выбрать канал 25 (описано выше)
- ✅ Разместить WiFi роутер и Zigbee координатор на расстоянии ≥ 2 метров друг от друга
- ✅ Первыми подключить все сетевые устройства (розетки, реле) — они усиливают mesh
- ✅ Использовать `tcp://` подключение к Dongle Max — это стабильнее USB

---

### Риск #2: Устаревание LocalTuya ключей ⚠️ СРЕДНИЙ

**Симптомы провала:** Через 3–6 месяцев WiFi Tuya устройства перестают работать. LocalTuya показывает "Cannot connect to device".

**Причины:**
- Tuya периодически обновляет Local Keys при прошивке устройств
- После обновления прошивки ключ меняется

**Превентивные меры:**
- ✅ Отключить автообновление прошивок в приложении Smart Life (важно!)
- ✅ Хранить Local Keys в отдельном файле
- ✅ Если устройство обновилось — получить новый ключ через Tuya Developer Console

---

### Риск #3: Перегрев ноутбука в режиме 24/7 ⚠️ ВЫСОКИЙ

**Симптомы провала:** Ноутбук зависает, самопроизвольно выключается. Через 4 месяца отказ из-за перегрева.

**Причины:**
- ASUS N551VW — игровой ноутбук с активным охлаждением, не рассчитанный на непрерывную работу
- Аккумулятор деградирует при постоянном подключении к питанию
- Вентиляционные отверстия на нижней панели могут забиваться пылью

**Превентивные меры:**
- ✅ Поставить ноутбук вертикально на подставку с открытыми вентиляционными отверстиями
- ✅ Каждые 2–3 месяца чистить от пыли
- ✅ В BIOS включить режим "Battery Care" (ограничение заряда до 80%) для сохранения АКБ
- ✅ В HA: Settings → System → Hardware → Power → отключить спящий режим
- ✅ Мониторить температуру CPU через интеграцию `systemmonitor`

---

### Риск #4: Нет резервных копий / Потеря конфигурации ⚠️ КРИТИЧЕСКИЙ

**Симптомы провала:** Случайное обновление HAOS привело к потере конфигурации. Восстановление заняло неделю.

**Причины:**
- Не были настроены автоматические бэкапы
- Снапшоты хранились только на ноутбуке (который и вышел из строя)

**Превентивные меры:**
- ✅ Настроить ежедневные снапшоты (описано в этапе 6)
- ✅ Установить Google Drive Backup (HACS) — копирование в облако
- ✅ Хранить Local Keys и credentials в отдельном файле в облаке (не только в HA)

---

### Риск #5: Яндекс меняет API ⚠️ СРЕДНИЙ

**Симптомы провала:** После обновления HA или Яндекс API лампочки YNDX и Алиса перестают работать через HA.

**Причины:**
- Яндекс периодически изменяет Skills API для Алисы
- Интеграция YSH зависит от сообщества разработчиков

**Превентивные меры:**
- ✅ Не удалять оригинальное приложение Яндекс
- ✅ Подписаться на GitHub репозиторий YSH интеграции для уведомлений
- ✅ Критические функции (реле, безопасность) реализовать через Zigbee, независимо от Яндекса

---

### Риск #6: SONOFF Dongle Max PoE не обнаруживается ⚠️ СРЕДНИЙ

**Симптомы провала:** После настройки Zigbee2MQTT не может подключиться к координатору.

**Причины:**
- Неправильный тип адаптера в конфигурации (нужен `ember`, а не `ezsp`/`zstack`)
- Firewall блокирует порт 6638
- Dongle получил другой IP

**Превентивные меры:**
- ✅ Всегда использовать статический IP для Dongle через DHCP Reservation
- ✅ Проверить `telnet 192.168.1.11 6638` — должно открыться соединение
- ✅ Тип адаптера для EFR32MG24: `ember` (НЕ `zstack`, НЕ устаревший `ezsp`)

---

### Риск #7: Устройства без нейтрали нестабильны ⚠️ СРЕДНИЙ

**Симптомы провала:** Реле без нейтрали (HOMMYN RLZBNN01/02, Tuya) мигают, не переключаются стабильно.

**Причины:**
- Реле без нейтрали требуют минимальный ток через нагрузку для питания
- Светодиодные лампы потребляют слишком мало тока

**Превентивные меры:**
- ✅ Для реле без нейтрали используйте лампочки минимум 7–10W
- ✅ Или установите конденсатор-байпас (обычно идёт в комплекте или продаётся отдельно)
- ✅ При проблемах — перейти на реле с нейтралью

---

### Риск #8: Алиса перестаёт управлять устройствами HA ⚠️ СРЕДНИЙ

**Симптомы провала:** "Алиса, включи свет" → "Не могу связаться с умным домом". Прямые команды в приложении HA работают, голосовые — нет.

**Причины:**
- Истёк токен OAuth (обычно действует 1 год)
- Изменился внешний URL (динамический IP, истёк домен)
- Яндекс недоступен из-за блокировок (маловероятно)

**Превентивные меры:**
- ✅ Использовать Nabu Casa или Cloudflare Tunnel с фиксированным доменом — не зависеть от динамического IP
- ✅ Записать дату истечения OAuth токена и обновить заранее
- ✅ Для критических устройств (реле, свет) всегда иметь физическую кнопку-резерв
- ✅ Все Станции (Миди, Лайт 2) работают через единый аккаунт — достаточно перепривязать один раз

## 9. Чеклист финального запуска

### Перед запуском

- [ ] Switch и PoE инжектор подключены и работают
- [ ] SONOFF Dongle Max получает IP от DHCP
- [ ] Статический IP назначен Dongle Max (192.168.1.11)
- [ ] HAOS установлена и доступна по http://192.168.1.10:8123
- [ ] Создан аккаунт администратора в HA
- [ ] Mosquitto broker установлен и запущен
- [ ] MQTT интеграция настроена в HA
- [ ] Zigbee2MQTT настроен с правильным адресом координатора и типом `ember`
- [ ] Zigbee2MQTT успешно запущен (нет ошибок в логах)

### Подключение устройств

- [ ] Все роутерные Zigbee устройства (розетки, реле) добавлены
- [ ] Все конечные Zigbee устройства (датчики, кнопки) добавлены
- [ ] Все устройства получили понятные имена
- [ ] LocalTuya настроен для WiFi устройств
- [ ] Яндекс Smart Home интеграция настроена
- [ ] Камера Cootli добавлена
- [ ] Диммер Arlight подключён (через IR-blaster или пропущен)

### Безопасность и надёжность

- [ ] Автоматические снапшоты настроены (ежедневно, 7 дней)
- [ ] Google Drive Backup или другой внешний бэкап настроен
- [ ] Мониторинг температуры CPU настроен
- [ ] Ноутбук стоит на подставке с продувом
- [ ] Автообновление прошивок в Smart Life отключено
- [ ] Local Keys всех Tuya устройств сохранены отдельно

### Голосовое управление (Алиса + Станция Миди)

- [ ] Внешний доступ к HA настроен (Nabu Casa или Cloudflare Tunnel)
- [ ] YSH интеграция установлена через HACS
- [ ] Навык в Яндекс Диалогах создан и привязан к внешнему URL HA
- [ ] Аккаунт Яндекса привязан в приложении через OAuth
- [ ] Устройства из HA видны в приложении Яндекс (раздел "Устройства")
- [ ] Станция Миди отвечает на голосовые команды для устройств HA
- [ ] Станция Лайт 2 тоже отвечает (единый аккаунт Яндекса)
- [ ] Устройствам даны понятные русские имена для голосовых команд

### Тестирование

- [ ] Каждое Zigbee устройство протестировано вручную из UI HA
- [ ] Каждая WiFi розетка/реле протестирована через LocalTuya
- [ ] Автоматизация протечки воды протестирована (поднести датчик к воде)
- [ ] Уведомления на телефон работают
- [ ] "Алиса, включи свет в [комнате]" — работает через Станцию Миди
- [ ] "Алиса, какая температура в спальне?" — возвращает данные из HA датчика
