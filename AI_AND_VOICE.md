> Проверено экспертизой (Fable) с верификацией по источникам, сентябрь 2026.
> Дополняет `MASTER_PLAN.md`.

# ЧАСТЬ 1. Какую модель использовать

## 1.1 Короткий ответ: любую

Гипотеза «получу от Home Assistant доступ и скормлю его той модели, которой пользуюсь» —
**верна**. Именно для этого существует протокол MCP: он не привязан к вендору.

**Смена ассистента стоит 10–30 минут. На стороне Home Assistant не меняется ничего.**

Пример перехода Claude Code → Codex:

```bash
codex mcp add ha-mcp --url http://homeassistant.local:9583/<секретный-путь>/mcp
```

Плюс скопировать свои заметки из `CLAUDE.md` в `AGENTS.md` — это почти дословный перенос.

## 1.2 Развилка, которая для вас критична

Клиенты делятся на два типа, и разница решает всё.

| Тип | Примеры | Откуда подключается | Работает через WireGuard? |
|---|---|---|---|
| **Командная строка / редактор** | Claude Code, Codex CLI, Cursor, Windsurf, Gemini CLI, Copilot | С вашего компьютера | ✅ Да |
| **Веб-версия** | claude.ai в браузере, ChatGPT в браузере | Из облака вендора | ❌ Нет |

Веб-клиенты физически не могут пройти через ваш VPN — соединение устанавливается серверами
вендора, которые о вашей домашней сети ничего не знают. Им нужен публичный адрес дома в интернете.

**Вывод для вас:** работайте через клиенты в командной строке. Claude Code, которым вы
пользуетесь, — правильный выбор. Ничего менять не нужно.

> Если когда-нибудь захочется подключить браузерную версию — понадобится российский VPS
> с обратным прокси. Это единственное оправданное исключение из правила «не выставлять
> Home Assistant в интернет».

## 1.3 Что ставить: ha-mcp

**Официальная интеграция MCP Server от Home Assistant не подходит.** Она открывает только
Assist API: включить, выключить, спросить состояние. **Создавать автоматизации она не умеет.**

Нужен **ha-mcp** — `github.com/homeassistant-ai/ha-mcp`.

| Показатель | Значение |
|---|---|
| Звёзд на GitHub | ~4600 |
| Последний релиз | 8.3.0, август 2026 |
| Инструментов | 88 |
| Установка | Дополнение прямо в Home Assistant, порт 9583 |
| Настройка клиента | Мастер генерирует конфиг для 15+ клиентов |

Что умеет: создание и правка автоматизаций, сценариев, сцен, панелей, помощников; чтение
истории и статистики; **разбор трассировок** («почему автоматизация не сработала»);
резервные копии; правка YAML (в бета-состоянии).

Реальный риск: проект неофициальный. При выходе новой версии Home Assistant может отставать
на несколько дней. 88 инструментов — большая поверхность, где модель может запутаться;
лечится включением поиска по инструментам.

## 1.4 Безопасность — обязательный минимум

Три факта, которые надо знать до подключения.

**Токены Home Assistant живут 10 лет и не ограничиваются по правам.** Токен даёт всё, что
может пользователь, который его создал.

**Реальное ограничение прав — список открытых сущностей**, а не токен.
Настройки → Голосовые помощники → Открыть доступ. Чего нет в списке — модель не видит.

**Главная угроза — не кража токена, а внедрение команд через данные.** Модель читает имена
устройств, события календаря, тексты уведомлений. В любом из этих текстов может оказаться
инструкция, которую модель примет за вашу.

### Настройка защиты

```
1. Создать отдельного пользователя Home Assistant «ai-agent»
   БЕЗ прав администратора. Токены выдавать от него.
   Без прав администратора закрыты настройки, дополнения и супервизор.

2. Открыть доступ только к тем сущностям, которыми реально управляем.
   Замки, ворота, сигнализацию — не открывать.

3. Первые недели держать ha-mcp в режиме «только чтение» (read_only_mode).
   Потом включить подтверждение на изменяющие действия.

4. Оставить включёнными автоматические копии перед правкой
   и скрытие секретов (redact_secrets).

5. git init в папке конфигурации, коммит раз в сутки.
   Любая ошибка модели становится git diff, а не раскопками.

6. Отдельный токен на каждый клиент, с понятным именем.
   Тогда отзыв точечный.

7. Не давать модели править конфиг Zigbee2MQTT.
   Поломка Z2M кладёт весь парк устройств разом.
```

## 1.5 Две модели на две разные задачи

| Задача | Модель | Почему |
|---|---|---|
| Повседневные команды в доме, круглосуточно | **YandexGPT** (`black-roland/homeassistant-yandexgpt`) | Дёшево, быстро, платится российской картой, хорошо понимает русский, работает через штатный Assist API |
| Создание и отладка автоматизаций | **Claude Code** или чем пользуетесь сейчас | Разбор YAML и трассировок — там, где нужна максимальная способность |

Наоборот не работает: сильная модель в роли круглосуточного обработчика команд — дорого
и медленно; YandexGPT в роли автора автоматизаций — не потянет.

Альтернативы YandexGPT, платимые из России: GigaChat, DeepSeek через компонент
`hasscc/ai-conversation`, принимающий любой OpenAI-совместимый адрес.

## 1.6 Где на самом деле возникает привязка к вендору

Не в Home Assistant. Настройка MCP переносится за минуты.

**Привязка возникает в накопленных инструкциях** — как устроен ваш дом, соглашения по именам,
на какие грабли вы уже наступили. Если это лежит в памяти конкретного вендора, при переходе
вы теряете всё.

**Решение:** держать эти знания обычным markdown-файлом в репозитории. Новый ассистент
прочитал файл — и он в курсе. Репозиторий у вас уже есть.

# ЧАСТЬ 2. Голос

## 2.1 Главный вывод: то, что вы видели у Яндекса, и есть ответ

Сценарии Яндекса с фразами запуска решают примерно 80% задачи. И для сценария с супругой
это правильный инструмент — лучше, чем свободная речь через модель.

### Как это работает

```
Супруга: «Алиса, мы ложимся спать»
              │
              ▼
   Яндекс Станция распознала фразу
              │
              ▼
   Сценарий в приложении «Дом с Алисой»
              │
              ▼
   Переключает скрипт Home Assistant,
   отданный Яндексу через yandex_smart_home
              │
              ▼
   Home Assistant делает что угодно:
   30 устройств, условия, задержки, уведомления
              │
              ▼
   Колонка отвечает заданной фразой
```

### Ограничения — знать заранее

| Параметр | Значение |
|---|---|
| Фраз на один сценарий | 1–3 |
| Сценариев на аккаунт | ~200 |
| Шаблоны и подстановки | **Нет.** Фразы — фиксированные строки |
| Передача параметров | **Нет.** «Поставь 22 градуса» с переменной невозможно |
| Распознавание вариаций | Алиса сопоставляет нестрого — склонения и мелкие отличия обычно проходят |

**Про параметры важно.** Числа Алиса и так понимает — своей встроенной грамматикой.
«Установи температуру 22» на отданном ей термостате работает без всяких сценариев.
Поэтому параметрические команды идут через правильную отдачу устройств, а фразы —
через сценарии. Это разные механизмы, не надо их путать.

## 2.2 Что ставить: ha-yandex-station-intents

`github.com/dext0r/ha-yandex-station-intents` — делает то же самое, но в масштабе и из
Home Assistant.

Вы перечисляете фразы в конфигурации — компонент **сам создаёт сценарии в облаке Яндекса**
и при срабатывании кидает в Home Assistant событие `yandex_intent`.

Что приходит в событии:
- текст команды
- **какая колонка услышала**
- комната

Второй пункт ценнее, чем кажется: «включи свет» может означать «в той комнате, где я стою».
Супруге не нужно уточнять помещение.

| Параметр | Значение |
|---|---|
| Максимум намерений | ~200 (ограничение платформы Яндекса) |
| Дополнительных фраз на намерение | до 3 |
| Символы во фразах | только кириллица, цифры, пробелы |
| Публичный адрес | **не нужен** |
| Что требуется | аккаунт Яндекса |
| Автор | dext0r — он же автор `yandex_smart_home` |

**Риск, о котором автор сам предупреждает:** компонент работает через недокументированный
API Яндекса. Яндекс может его сломать. Запасной вариант всегда есть — создавать сценарии
руками в приложении, как в п. 2.1.

## 2.3 Три проекта, которые легко перепутать

| Проект | Что делает | Нужен внешний адрес |
|---|---|---|
| **dext0r/yandex_smart_home** | Отдаёт устройства из HA в Алису | Нет (облачный режим) |
| **AlexxIT/YandexStation** | Управляет колонками из HA: озвучка, отправка команд | Нет |
| **dext0r/ha-yandex-station-intents** | Произвольные фразы → события в HA | Нет |
| **AlexxIT/YandexDialogs** | Свободная речь → HA через навык Яндекса | **Да** |

Первые три — то, что вам нужно. Четвёртый разобран ниже.

## 2.4 Чего сделать нельзя — проверено

**Микрофон Яндекс Станции недоступен.** Превратить колонку в микрофон для Home Assistant
невозможно — Яндекс не отдаёт аудиопоток. Автор YandexStation прямо говорит, что не может
это реализовать. Это закрывает целый класс идей.

**Алису нельзя подключить к своей модели.** Собственная модель Яндекса на станциях закрыта,
подставить свой сервер нельзя.

**Свободная речь через навык — технически да, практически нет.** Через `YandexDialogs`
произвольная фраза действительно попадает в Home Assistant, и ответ модели произносится
колонкой. Но:

- Обращение звучит как «Алиса, попроси навык *Мой дом* включить…» либо надо сначала войти в навык
- **Навык обязан ответить примерно за 3 секунды** — модель просто не успевает
- Сессия закрывается по молчанию

Это канал для энтузиаста, не для супруги.

## 2.5 Если Алисы не хватит: отдельные голосовые точки

Полностью свой голосовой контур в Home Assistant по-русски работает. Компоненты есть:

**Распознавание речи (что выбрать под ваш процессор):**

| Вариант | Задержка | Русский | Оплата |
|---|---|---|---|
| **Яндекс SpeechKit** (`black-roland/homeassistant-yandex-speechkit`) | 0.5–1.5 с | Лучший из всех | Рублями, копейки |
| **Vosk**, малая модель | менее 1 с | Хорошо для команд | Бесплатно, локально |
| Whisper `small` | 2–5 с | Приемлемо, путается в именах | Бесплатно, локально |
| Whisper `medium` | Не тянет на этом процессоре | — | — |

**Синтез речи:**

| Вариант | Качество |
|---|---|
| **Яндекс SpeechKit TTS** | Уровень Алисы, лучшее что есть |
| **Silero** | Заметно естественнее Piper, локально |
| Piper (русские голоса) | Разборчиво, но явно синтетично |

**Слабое место — слово пробуждения.** Готовых русских слов пробуждения хорошего качества нет.
«Окей Набу» русские произносят, и оно срабатывает приемлемо. Своё русское слово обучить можно,
но это выходные с подбором порогов и результат уровня самоделки.

**Задержка полного контура** с облачным распознаванием и облачной моделью:
**3–6 секунд** от конца фразы до ответа. Локальная модель на вашем процессоре — 10+ секунд,
не вариант.

## 2.6 Ключевая мысль про сценарий с супругой

Я формулировал это как «надёжность против гибкости». Fable уточнил формулировку, и уточнение
важнее исходной мысли.

**Дело не в фиксированных фразах против свободных. Дело в том, что происходит при отказе.**

Фраза, которая работает всегда, формирует привычку. Модель, которая права в 90% случаев
и отвечает через 5 секунд, учит не пробовать.

И второе, более практичное:

> **Умным надо делать сценарий, а не речевой интерфейс.**

Пример. Хочется сказать: «мы ложимся, но оставь свет в коридоре для ребёнка».
Свободная речь для этого не нужна. Нужен сценарий «мы ложимся спать», который **сам**
проверяет, дома ли ребёнок, и сам оставляет свет.

Супруга говорит простую фразу. Сложность живёт в автоматизации, а не в распознавании.
Это и надёжнее, и работает быстрее, и вам это писать — через Claude Code.

Плюс: нестрогое сопоставление у Алисы, три формулировки на сценарий и штатная грамматика
для чисел покрывают почти всё, что семья реально произносит вслух.

## 2.7 План по голосу

### Уровень A — сделать сразу

**Стоимость: 0 ₽. Время: вечер.**

1. `yandex_smart_home` через облачный режим — отдать устройства Алисе
2. `YandexStation` — озвучка и уведомления через колонки
3. `ha-yandex-station-intents` — фразы для сложных сценариев

На каждый бытовой сценарий — 2–3 формулировки и голосовое подтверждение:

```
«мы ложимся спать» / «спокойной ночи» / «отбой»
«мы уходим» / «уходим из дома»
«включи режим кино» / «давай кино»
«я дома» / «мы вернулись»
```

Использует колонки, которые уже куплены. Задержки нет. Осечек практически нет.

### Уровень B — если фиксированных фраз станет мало

**Стоимость: 0–8 000 ₽. Время: выходные.**

Одна голосовая точка (ESP32-S3 или Home Assistant Voice PE) в комнате, где реально
возникают свободные запросы. Распознавание — Яндекс SpeechKit, синтез — Silero или SpeechKit,
режим «сначала локальные намерения, модель как запасной вариант».

**Сначала пробуете сами.** Показывать семье — только если приживётся у вас.

### Уровень C — не делать

- Навык Яндекса как семейный интерфейс — обращение «попроси навык» и лимит в 3 секунды
- Whisper `medium` и локальная модель на этом процессоре
- Замена Яндекс Станций на голосовые точки — микрофоны у Станций лучше
- Nabu Casa — не оплатить

## Что не подтверждено и требует проверки на месте

- Точный лимит фраз на сценарий у Яндекса: 3 или 4 — источники расходятся
- Актуальные цены Яндекс SpeechKit
- Текущие ограничения ChatGPT по плану подписки на изменяющие инструменты MCP — меняются часто
- Точный таймаут навыков Яндекса (исторически 3 секунды)
